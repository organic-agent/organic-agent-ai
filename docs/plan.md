# organic-agent-ai 계획

wes(웨딩 사진 셀렉 서비스)의 AI 기능을 담당하는 서버의 제품·기술 계획.
2026-08-17, 인터뷰 3건(정식 2 + 비정규 메모 1)을 반영해 방향을 확정한 버전.

---

## 1. 배경 — 인터뷰가 바꾼 것

초기 계획은 "AI 1차 셀렉 초안" 단일 기능이었다. 인터뷰 결과가 우선순위를 뒤집었다:

| 인터뷰 결론 | 계획에 미친 영향 |
|---|---|
| 돈을 내는 쪽은 작가/스튜디오, 근거는 **작가 업무 시간 절감** | 부부 편의 중심 → 작가 절감 중심으로 우선순위 재배열 |
| 셀렉보다 **보정 요청 커뮤니케이션**이 더 큰 고통 | 보정 요청 구조화가 첫 번째 진짜 LLM 기능 |
| **앨범 미리보기·에디터**에 가장 좋은 반응 (2/3 결제 의향) | 앨범 에디터를 P1으로. 단, 본체는 웹 에디터고 AI는 보조 |
| AI 셀렉은 "수천→수백 + 최종은 사람"이면 긍정적 | 기존 초안 설계 유지, 우선순위만 P3로 |
| 작가가 의도한 흔들림·눈감김 컷을 AI가 지우면 안 됨 | 품질 점수는 정렬·제안 근거로만, 하드 필터 금지 |
| 기존 편집 프로그램(Lightroom 등)과 경쟁 금지 | 편집 자체는 범위 밖. 커뮤니케이션·구성 단계만 다룬다 |
| 현실 가격 월 3~5만 원 (회사 최대 10만) | 갤러리당 LLM 원가를 낮게 — vision 전수 스캔 최소화 |
| 과금 주체(고객 vs 스튜디오) 미결 | 열린 질문으로 유지. P1·P2가 스튜디오 과금 근거를 쌓는 구성 |

## 2. 로드맵

```
공통 인프라: 사진별 분석 (embedder 확장)
    │   얼굴/피사체 바운딩 박스 + 장면 태그 — 경량 모델 위주, LLM 최소화
    │
    ├─ P1: 앨범 미리보기·에디터  ← AI: 자동 레이아웃 초안, 크롭 안전 감지
    ├─ P2: 보정 요청 구조화     ← AI: 모호한 요청 → 규격화된 요청 (LLM 적소)
    └─ P3: AI 1차 셀렉 초안     ← AI: 목표 장수까지 초안 채우기 (기존 설계)
```

### 공통 인프라 — 사진별 분석

embedder가 이미 갤러리당 1회 원본을 디코드하므로, 같은 패스에서 추가로 뽑아 저장한다:

- **얼굴/주요 피사체 바운딩 박스** — 경량 검출 모델(LLM 아님). P1 크롭 감지·자동 레이아웃의 재료
- **장면 태그** (본식/야외/스튜디오, 클로즈업/전신/단체 등) — P1 레이아웃 다양성, P3 커버리지 축
- 저장: `photos`에 컬럼 추가 또는 별도 테이블 (스키마는 wes Flyway 소유)

원가 원칙: **갤러리 전수 처리는 경량 모델, LLM은 사용자 요청 단위의 소규모 호출에만.**

### P1. 앨범 미리보기·에디터

- **본체는 웹 에디터** (organic-agent-test-web + wes): 실제 앨범 규격 프리셋 렌더링, 펼침면
  단위 드래그앤드롭, 확정 배치를 작가에게 그대로 전달. 셀렉 제출(`SUBMITTED`) 이후 단계라
  기존 도메인 흐름에 자연스럽게 이어진다.
- **AI 몫 (organic-agent-ai)**:
  - *자동 레이아웃 초안* — 셀렉된 사진의 얼굴 위치·방향(가로/세로)·장면 태그·타임라인으로
    초기 펼침면 배치 생성. 배치 Lambda (셀렉 제출 시 1회)
  - *크롭 안전 감지* — 규격 크롭 시 얼굴/피사체 잘림 경고. 저장된 바운딩 박스와 크롭 영역의
    기하 계산이라 **런타임 AI 호출 없음** (에디터가 실시간으로 계산)
- 효과: 부부는 구성을 직접 확인·수정, 작가는 확정 배치대로 제작만 → 시안 왕복 제거

### P2. 보정 요청 구조화

- 작가가 가능/불가 편집 방식과 가이드를 사전 등록 → 부부의 모호한 요청("자연스럽게 해주세요")
  + 부위 표시 + 참고 이미지를 LLM이 **구조화된 요청**(사진 · 부위 · 강도 · 참고)으로 변환,
  불가능한 요청은 접수 전에 안내하고 합의를 유도.
- 작가들이 이미 수동으로 하는 통제(가이드 제공, 횟수 제한)의 자동화 — 워크플로를 바꾸지 않고
  줄인다. wes의 retouch 도메인(라운드·횟수 제한) 위에 얹는다.
- **대화형 워크로드**: 사용자가 기다리는 흐름이라 배치 Lambda가 아닌 저지연 동기 API 필요.
  페이로드가 작아(텍스트 + 사진 1~2장) 원가는 낮다.
- 효과: 재수정 반복 감소 = 작가 시간 절감이 정량적으로 보임 → 결제 근거가 가장 명확한 AI 기능

### P3. AI 1차 셀렉 초안

기존 상세 설계 유지 (아래 §5), 인터뷰 경고 2건 반영:

- 품질 점수로 **하드 필터링 금지** — 의도적 아웃포커스·눈감김 컷 보호. 점수는 정렬·제안
  근거로만 쓰고, AI가 제외한 사진도 쉽게 되살리는 UI 전제
- 초안의 소비자는 부부로 한정 (고객 기준 ≠ 작가 기준)

## 3. 아키텍처

```
wes 백엔드 (Kotlin/Spring) ── 실행 조건 검증 · 잡/요청 API · 도메인 소유
    │
    ├─ 배치 트리거 (Lambda EVENT, {"galleryId", "jobId"})
    │    └─ organic-agent-ai 배치 파이프라인: 사진 분석 · 자동 레이아웃 · 1차 셀렉
    │       (embedder 패턴: handler.py / __main__.py 동일 코드, DB 직접 읽고 씀, 멱등)
    │
    └─ 동기 호출 (저지연 API)
         └─ organic-agent-ai 대화형 엔드포인트: 보정 요청 구조화
    
공유 Postgres(RDS) · S3 (원본 / previews)
```

두 가지 실행 모양:

| 워크로드 | 모양 | 예 |
|---|---|---|
| 배치 (갤러리/앨범당 1회) | ECR 컨테이너 Lambda, EVENT 호출 | 사진 분석, 레이아웃 초안, 1차 셀렉 |
| 대화형 (사용자 대기) | 동기 API (Lambda URL 또는 wes 경유) | 보정 요청 구조화 |

**Bedrock**: `AnthropicBedrockMantle(aws_region="ap-northeast-2")`, 모델 `anthropic.claude-opus-5`
(미제공 시 크로스 리전 프로필 `apac.anthropic.…`), structured outputs 필수, 루브릭 prompt
caching. 상세 규칙은 `.claude/rules/bedrock.md`.

## 5. P3 상세 설계 (확정분, 요약)

> 2026-08-19 이후 P3 상세는 `photoselect/docs/plan.md`(4단계 셀렉 퍼널: 품질→미학→세밀
> 비교→개인화 큐레이션)가 구체화·대체한다. 아래는 그 이전 확정분 요약.

- **실행 조건** (wes 검증): 갤러리 OPEN · 마감 전 · 전 사진 EMBEDDED · 목표 장수 존재 ·
  현재 선택 < 목표 · 활성/완료 잡 없음 · 미제출 상태
- **Stage A** — pgvector 클러스터(union-find) → 클러스터별 미리보기(`preview_key`)를 vision으로
  품질 평가(초점·노출·눈감김·표정·구도), structured outputs, asyncio 병렬
- **Stage B** — 점수 + 클러스터 + `taken_at` 타임라인 + 고정된 수동 선택으로 남은 슬롯을
  중복 제거 · 커버리지 기준으로 채움. 선택마다 한 줄 근거
- **가드레일** (LLM 불신): 무효 photo_id 거부, 수동 선택 불가침, 개수 결정적 보정,
  전체 < 목표면 전부 선택 + `shortfall` 기록
- **잡 라이프사이클**: PENDING→RUNNING→COMPLETED/FAILED, 결과 쓰기+상태 전이 단일 트랜잭션,
  멱등 재실행, FAILED만 재시도, 완료 초안 재생성·자동 재충전 금지, 자동 확정·제출 금지
- **정책**: `photo_ratings`(개인 취향) 입력 제외
- 불변식 상세: `.claude/rules/pipeline.md`

## 6. 구현 순서

1. **공통 스캐폴드 + 스파이크** — embedder 구조 복제, Bedrock 리전·모델 가용성 확인,
   소규모 end-to-end 실측 (시간·원가)
2. **공통 인프라** — embedder에 얼굴/피사체 검출 + 장면 태그 추가, wes 마이그레이션
3. **P1** — wes 앨범 도메인 + 웹 에디터 (별도 트랙) / AI: 자동 레이아웃 초안 배치, 크롭 감지용
   데이터 제공
4. **P2** — 작가 편집 메뉴 등록(wes) + 구조화 동기 API + 접수 UI
5. **P3** — 1차 셀렉 파이프라인 (V22 마이그레이션, aiselection 도메인, Stage A/B)
6. **평가** — `../dataset` 골든 셋: 레이아웃 초안 품질, 구조화 정확도, 셀렉 일치율
7. **배포** — Terraform (`../organic-agent-infra`), IAM(bedrock:InvokeModel · S3 · RDS)

## 7. 리스크 & 열린 질문

- **과금 주체 미결** (고객 vs 스튜디오) — P1·P2가 스튜디오 과금 근거를 쌓지만 결론은 추가 검증 필요
- **P1의 AI 비중이 작음** — 앨범 에디터 성공의 관건은 렌더링·UX. organic-agent-ai의 첫 진짜
  LLM 기능은 P2가 될 가능성이 높음
- **자동 레이아웃 초안의 품질 바닥** — 어설픈 초안은 신뢰를 깎는다. 규격 프리셋별 골든
  레이아웃으로 평가 기준을 먼저 만든다
- **Lambda 15분 제한** — 수백 장 갤러리 배치. 미리보기 사용 + 병렬화로 대응, 실측 초과 시
  ECS Fargate 전환
- **Bedrock 모델의 ap-northeast-2 가용성** — 스파이크에서 최우선 확인
