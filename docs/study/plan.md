# 학습 검증 시스템 플랜

학습 자료를 "봤다"와 "쓸 수 있다"는 다르다. 이 플랜은 학습을 **검증 가능한 형태**로
만드는 스킬·클로드 셋팅을 정의한다.

## 원칙

1. **회상(retrieval) 우선** — 다시 읽기보다 꺼내 쓰기가 기억을 만든다. 검증은 항상
   "설명해봐라 / 계산해봐라"이지 "읽었냐"가 아니다.
2. **이론에는 실습을 붙인다** — 개념 하나마다 돌려 볼 수 있는 코드를 짝지어 둔다
   (`01-recsys/lab/`). 이론만 읽고 넘어가면 퀴즈의 L2(계산)에서 매번 막힌다.
3. **설계안이 최종 시험지** — 모든 검증 문제의 종착점은 `photoselect/docs/plan.md`의
   실제 결정("왜 λ = f(증거량)인가", "L4 24GB에 12B FP16이 올라가는가")이다. 일반 지식
   퀴즈는 수단일 뿐이다.
4. **질문은 한 번에 하나** — 답을 듣고 다음 질문을 조정한다. 여러 개 나열 금지.
5. **틀린 것은 큐로** — 오답은 `review-queue.md`에 쌓고, 다음 세션 시작 시 먼저 소화한다.

## 구성요소

### 1. `/study-quiz` 스킬 (핵심 — 구현 완료, `.claude/skills/study-quiz/`)

사용법:

```
/study-quiz 01          # 01-recsys 영역 퀴즈
/study-quiz 05 양자화    # 영역 내 특정 주제
/study-quiz review      # review-queue.md의 복습 항목 소화
/study-quiz mentor      # 멘토 질문 모의 방어 (설계안 전체)
```

동작:

- 해당 영역의 `notes.md`(내가 정리한 것)와 `materials.md`(학습했다고 표시한 것),
  그리고 실습 폴더(`lab/`)가 있으면 그 코드까지 읽고, **학습한 범위 안에서만** 출제한다.
  안 배운 것을 물어 좌절시키지 않는다.
- 실습이 있는 개념은 코드 자체를 문제로 쓴다 — "step1에서 `fit_intercept=False`인 이유는",
  "step4의 `_dedup_by_cluster`를 끄면 어떤 지표가 먼저 나빠지는가".
- 문제는 3단계를 섞는다:
  - **L1 회상**: "nDCG는 무엇을 측정하고 DCG와 어떻게 다른가?"
  - **L2 응용·계산**: "홀드아웃 3쌍 × 8명 = 24표본에서 정확도 62%가 나왔다. 우연(50%)과
    구분된다고 말할 수 있는가? 계산해봐라."
  - **L3 설계 연결**: "우리 설계는 MMR을 쓴다. MMR 없이 취향 점수 상위 N장만 주면
    구체적으로 어떤 실패가 나는가?"
- 한 번에 한 문제. 답을 들으면: 맞은 부분 확인 → 빠진 부분 지적 → 필요하면 꼬리 질문
  → 그 다음에 다음 문제.
- 세션 종료 시(5~7문제 또는 사용자가 그만) 결과를 기록한다:
  - `progress.md`에 세션 요약 1줄 (날짜, 영역, 정답률, 약점)
  - 틀렸거나 애매했던 개념을 `review-queue.md`에 추가 (개념, 왜 틀렸는지, 재검증 예정일)

### 2. `progress.md` — 진행 로그

스킬이 append하는 단순 테이블. 사람이 봐도 한눈에 들어오는 것이 목표.

```
| 날짜 | 영역 | 모드 | 결과 | 약점 |
|---|---|---|---|---|
| 2026-08-25 | 01-recsys | quiz | 5/7 | Bradley-Terry 우도 유도, MRR vs MAP 구분 |
```

### 3. `review-queue.md` — 복습 큐 (간이 spaced repetition)

```
- [ ] Bradley-Terry: 선호 확률 식을 유도 못함 — 재검증 08-27 (1차 오답 08-25)
```

규칙: 오답 → 2일 후 재검증. 재검증 통과 → 1주 후 한 번 더 → 통과 시 체크(완료).
재검증 또 실패 → 자료로 돌아가서 다시 학습 후 큐 유지.

### 4. 마일스톤 검증 — `/study-quiz mentor`

영역 퀴즈와 별개로, 설계안 전체를 놓고 **멘토/면접관 역할**로 방어 시험을 본다.
`photoselect/docs/plan.md`·멘토 브리핑 문서의 실제 질문(예: "L4에서 0.3초/장이
현실적인가", "λ 설계의 통계적 근거는")을 소재로 쓴다. 시점:

- W2 말 — 쌍 비교 실험 결과 해석 방어 (01+02 검증)
- W3 말 — VLM 처리량 실측 방어 (05 검증)
- W6 — 파이프라인 전체 방어 (03+04 포함)
- 11월 최종점검 전 — 전 영역 리허설. 이력서 두 축("추천 시스템 설계", "자체 GPU VLM
  서빙")을 면접 답변 형태로 말해보는 것 포함.

## 클로드 셋팅

- 스킬 위치: `.claude/skills/study-quiz/SKILL.md` (프로젝트 스킬, 이 repo에서만 동작)
- 메모리 연동: 퀴즈에서 반복적으로 드러나는 약점·선호 학습 방식은 클로드가 자동 메모리에
  기록하므로 별도 셋팅 불필요
- git: `study/`와 스킬은 개인 학습물이다. 커밋하려면 규칙상 `docs:` 직접 커밋이 허용되지만
  (`.claude/rules/git-workflow.md`), 팀 공유 repo라면 `.gitignore`에 `study/`를 추가하는
  선택지도 있다 — **결정 필요**
- 확장 후보 (지금은 안 만듦, 필요해지면):
  - `/study-feynman` — 퀴즈가 아니라 "백지에 설명" 검증. 개념 하나를 처음부터 설명하게
    하고 구멍만 짚는 모드. quiz의 L1이 잘 되면 승격용으로 도입
  - 주간 cron(스케줄 에이전트)으로 review-queue 리마인드 — 큐가 실제로 쌓이기 시작하면 도입
