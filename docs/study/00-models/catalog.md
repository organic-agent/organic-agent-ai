## 1. MediaPipe Face Landmarker

| | |
|---|---|
| **무엇을 하나** | 사진에서 얼굴을 찾고, 얼굴마다 랜드마크 478개와 **blendshape 52개**를 낸다 |
| **무엇을 학습했나** | 얼굴 사진과 랜드마크 좌표의 쌍. Google이 학습해 배포한 것을 그대로 쓴다 |
| **입력 / 출력** | RGB 이미지 → `face_count`, `eyes_open`, `smile`, `max_face_ratio` |
| **왜 골랐나** | CPU에서 사진당 0.1초. 무료·경량이고 얼굴 신호는 이것으로 충분하다 |

### blendshape가 무엇인가

**"표정을 52개 슬라이더로 표현한 것"** 이다. 원래는 3D 아바타를 움직이려고 만든 개념이다 —
`eyeBlinkLeft`, `mouthSmileRight` 같은 이름의 값이 각각 0~1로 나온다.

우리 러너는 그중 둘만 쓴다.

```python
eyes_open = 1 - max(eyeBlinkLeft, eyeBlinkRight)   # 얼굴마다, 그중 최소값
smile     = (mouthSmileLeft + mouthSmileRight) / 2 # 평균
```

`eyes_open`이 **전원의 최소값**인 것이 중요하다 — 단체 사진에서 한 명만 눈을 감아도
그 컷은 쓰기 어렵기 때문이다.

### ⚠ 확인해야 할 것 — 이 모델의 미해결 이슈

스파이크 리포트(08-19)의 관찰:

> 2인 컷(얼굴 bbox 비율 ~0.036)에서 `eyes_open` 최소값이 0.2대로 낮게 나온다 —
> 실제 눈 감김인지 blendshape가 작은 얼굴에서 불안정한 건지 **확인 필요**

`lab/step2` [4]가 이 질문에 **라벨 없이** 접근하는 방법을 보여 준다 —
사진을 좌우 반전해도 정답은 안 바뀌므로, 반전 전후 점수 차이가 곧 **잡음의 크기**다.
12장 표본에서 3장이 반전만으로 0.3 넘게 흔들렸다. 표본이 작아 결론은 못 내지만
**방법은 확인됐고, 라벨링보다 훨씬 싸다.**

## 2. ARNIQA — 기술 품질

| | |
|---|---|
| **무엇을 하나** | "이 사진이 **잘 찍혔는가**" 하나의 점수로 (흐림·노이즈·압축·노출) |
| **무엇을 학습했나** | 왜곡을 인위적으로 넣은 이미지 쌍으로 **자기지도 학습** → 사람 평가 데이터셋으로 회귀 |
| **입력 / 출력** | RGB 이미지(+ 절반 크기) → `technical_score` 0~1 (실측 대역 0.49~0.52) |
| **왜 골랐나** | WACV 2024, Apache-2.0. 참조 이미지 없이(no-reference) 동작 |
| **비고** | `torch.hub`로 받는다(캐시 107MB + 백본 ResNet50 98MB). 채택 시 커밋 SHA 고정 + 가중치 번들 필요 |

### "자기지도 학습"이 여기서 뜻하는 것

사람이 "이 사진 품질 7점"이라고 라벨을 단 데이터는 비싸다. ARNIQA는 그걸 우회한다.

```
같은 사진에 같은 왜곡을 넣은 두 장  →  임베딩이 가까워야 한다
다른 왜곡을 넣은 두 장            →  멀어야 한다
```

**"왜곡의 종류와 세기"를 표현하는 공간을 라벨 없이 학습**하고,
그다음에 작은 사람 평가 데이터셋으로 점수 회귀만 붙인다.

> 이 구조를 알면 한계도 보인다 — **학습에 쓴 왜곡의 종류만 잘 잡는다.**
> `lab/step2`에서 '많이 흐리게'에는 29배 반응하는데 '살짝 흐리게'는 1.9배(애매)인 것이
> 그 예다. 미세한 흐림은 우리 용도로는 못 믿는다.

### ⚠ 확인해야 할 것

- **점수 대역이 좁다** (0.49~0.52). 갤러리 내 백분위로 바꿔 쓰는데,
  원점수 대역이 좁으면 **백분위가 잡음의 순위가 된다** (02 step9 [C])
- 사진당 0.369초로 경량 3종 중 가장 느리다 (스파이크 1차 실측)
- 라이선스 원문 재확인 + 커밋 SHA 고정이 채택 전 조건

## 3. LAION Aesthetic Predictor v2 — 미학

| | |
|---|---|
| **무엇을 하나** | "이 사진이 **보기 좋은가**" 하나의 점수로 |
| **무엇을 학습했나** | CLIP 임베딩 → 사람이 매긴 미학 점수(AVA 등)로 학습한 **작은 MLP** |
| **입력 / 출력** | RGB 이미지 → `aesthetic_score` (AVA 1~10 축, 실측 대역 5.9~6.1) |
| **왜 골랐나** | Apache-2.0. CLIP 임베딩을 **다른 용도와 공유**할 수 있다 |

### 구조가 두 층이라는 것이 중요하다

```
사진  →  [CLIP ViT-L/14]  →  임베딩 768차원  →  [MLP 5층]  →  점수 하나
         └─ 933MB, 범용 ─┘                    └─ 3.7MB, 미학 전용 ─┘
```

**무거운 쪽은 CLIP이고 미학 부분은 3.7MB짜리 MLP다.** 즉 CLIP 임베딩을 한 번 뽑아 두면
미학 점수는 거의 공짜로 얻는다. 그리고 그 임베딩은 다른 데도 쓸 수 있다 —
러너 주석이 *"CLIP 임베딩은 서비스에서 장면 태그·취향 신호와 공유되는 자산"* 이라고 적은 이유다.

### '품질'과 '취향'은 다른 축이다

`lab/step2`의 결과가 이걸 선명하게 보여 준다.

```
흑백으로 만들면  →  ARNIQA(품질) 내려감 (−0.198)
                   LAION(미학)  올라감 (+0.066)
```

**흑백 사진은 기술 점수가 떨어지지만 사람들은 예쁘다고 본다.**
LAION은 사람의 취향 평균을 학습했으니 그렇게 반응하는 것이 맞다.

> 그래서 `plan.md`의 prior가 둘을 **더한다**: `technical_pct·w_t + aesthetic_pct·w_a`.
> 하나만 쓰면 한쪽 축을 통째로 잃는다.

### ⚠ 확인해야 할 것

- LAION은 **"사람들 평균의 취향"** 이다. 우리 부부의 취향이 아니다 —
  개인화는 λ·pref가 맡는다(01 영역). 이 점수는 **개인화 이전의 기준선**이다
- 웨딩 사진에 맞게 학습된 모델이 아니다. AVA는 일반 사진 데이터셋이다

## 4. 오픈 VLM — 고정 축 태그와 캡션

| | |
|---|---|
| **무엇을 하나** | 사진을 보고 **정해진 어휘 안에서** 5개 축 태그 + 한국어 캡션 1문장 |
| **무엇을 학습했나** | 이미지-텍스트 쌍 대규모 사전학습 + 지시 튜닝. 우리는 **학습 안 하고 프롬프트만 쓴다** |
| **입력 / 출력** | 이미지 + 프롬프트 → `{scene, framing, lighting, expression, subjects, caption}` |
| **후보** | Gemma 3 12B / Qwen2.5-VL 7B (31B 비교 후 확정) |
| **왜 골랐나** | **이미지를 외부로 안 보낸다**(CLAUDE.md 데이터 원칙) → 자체 GPU에서 도는 오픈 모델 |

### 어떻게 "정해진 어휘 밖으로 못 나가게" 하나

**guided decoding** (Ollama에서는 structured outputs)을 쓴다.
JSON 스키마의 `enum`을 주면 모델이 그 밖의 토큰을 아예 생성할 수 없다.

> 이건 프롬프트로 부탁하는 것이 아니라 **디코딩 단계에서 강제**하는 것이다.
> 그래서 `vlm_tag.py`의 주석이 *"여기서 나오는 `unknown`/`none`은 파싱 실패가 아니라
> 모델의 실제 선택"* 이라고 못 박아 뒀다.

### 실측 (2026-08-25, gemma3:12b 4bit 로컬, 50장 사람 채점)

| 축 | subjects | framing | expression | caption | lighting | **scene** |
|---|---|---|---|---|---|---|
| 정확도 | 98% | 92% | 90% | 86% | 84% | **74%** |

**이 숫자를 그대로 인용하면 안 된다.** 02 step8 [A]에서 확인했듯
`scene` 정확도는 **갤러리의 장면 분포에 따라 0.90 ↔ 0.76으로 바뀐다.**
74%는 snap이 68%인 표본에서 잰 값이다.

### ⚠ 확인해야 할 것

- **처리량 미검증** — 1,000장 ≤ 6분은 vLLM 연속 배치가 있는 L4에서만 잴 수 있다
- **예식 장면 5개 값(entrance/vow/ring/family/group) 미검증** — 데이터셋에 본식 사진이 없다
- 프롬프트 2차 실측 대기 (`scene` 74→85%, `lighting` 84→90% 목표)
- 12B vs 7B 원가 비교 미실행
- Gemma ToU 상업 조건 재확인

## 5. DINOv2 — 임베딩 (미착수)

| | |
|---|---|
| **무엇을 하나** | 사진 하나를 **벡터 하나**로 바꾼다. 비슷한 사진은 비슷한 벡터가 된다 |
| **무엇을 학습했나** | 라벨 없이 이미지만으로 자기지도 학습 (Meta) |
| **입력 / 출력** | RGB 이미지 → 임베딩 벡터 (수백~천 차원) |
| **어디에 쓰나** | A-6 **근접 중복 클러스터**(연사 묶기), MMR의 유사도, 취향의 미세 재정렬 |

### 왜 필요한가

웨딩 갤러리는 연사(burst)라 거의 같은 컷이 3~8장씩 붙어 있다.
01 step4에서 봤듯 **점수 상위 30장을 그냥 자르면 쌍둥이가 통째로 딸려 들어온다.**
그걸 묶으려면 "이 두 사진이 얼마나 닮았나"를 재야 하고, 그게 임베딩의 일이다.

01의 합성 갤러리에서 잰 대역:

```
같은 클러스터(연사)        코사인 0.885
같은 장면, 다른 클러스터    코사인 0.383
무관한 두 장              코사인 0.017
```

### ⚠ 확인해야 할 것

- **아직 한 번도 안 돌렸다.** 위 숫자는 전부 합성 데이터의 가정이다
- 실제 연사가 정말 0.9 근처인지, 클러스터 임계값을 얼마로 할지 미정
- pgvector에 넣을 차원 수·인덱스 방식 미정
- **03 영역(임베딩)이 이 모델을 다룬다** — 지금은 카탈로그에만 있다

## 우리가 학습하지 않는다는 것

**다섯 모델 전부 남이 학습한 것을 그대로 쓴다.** 우리가 학습하는 것은 딱 하나다 —

```
Bradley-Terry 취향 벡터 w   (고객 한 명당 33차원)
```

01 영역 전체가 그 하나를 다룬다. 나머지는 **조합과 평가**의 문제다.

> 이것이 `study/README.md`가 말하는 *"ML 연구가 아니라 AI 엔지니어링"* 의 실질이다.
> 모델을 만드는 것이 아니라 **고르고, 붙이고, 그 판단을 설명할 수 있게 되는 것**.
>
> 그래서 이 영역의 목표도 "모델을 만들 줄 안다"가 아니라
> **"이 모델이 무엇에 반응하고 어디서 못 믿는지 말할 수 있다"** 이다.
