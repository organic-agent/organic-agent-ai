# study — AI 엔지니어링 학습

AI 셀렉터 설계안(`photoselect/docs/plan.md`)을 구현·해석하는 데 필요한 기본기를 채우는
개인 학습 공간이다. 목표는 ML 연구가 아니라 **AI 엔지니어링** — 기존 모델을 조합해
추천 로직·평가·서빙을 만들고, 그 판단의 근거를 스스로 설명할 수 있게 되는 것.

## 폴더 구조

```
study/
├── README.md          ← 이 파일. 개요와 학습 순서
├── plan.md            ← 학습 검증 시스템 플랜 (스킬·클로드 셋팅)
├── progress.md        ← 학습 진행 로그 (스킬이 갱신)
├── review-queue.md    ← 오답·약점 복습 큐 (스킬이 갱신)
├── basics/            ← **0단계 앞: 수식 없는 기초 A~E** (선형대수·확률·ML·평가·VLM)
├── 00-models/         ← **0순위: 우리가 쓰는 모델들** (+ lab/ 실습 코드)
├── 01-recsys/         ← 1순위: 추천 시스템 기초 (+ lab/ 실습 코드)
├── 02-ml-stats/       ← 2순위: ML/통계 기초 (+ lab/ 실습 코드)
├── 03-embeddings/     ← 3순위: 임베딩과 표현학습
├── 04-vlm-llm/        ← 4순위: VLM/LLM 동작 원리
└── 05-serving-gpu/    ← 5순위: 추론 서빙과 GPU
```

각 영역 폴더는 두 파일을 가진다 (00·01·02는 실습 폴더가 추가로 있다):

- `materials.md` — 검증된 학습 자료 목록 (필수/선택, 링크·시간·커버 개념)
- `notes.md` — 학습하며 내 언어로 정리한 노트. **자료 요약 복사가 아니라, 설계안의 어느
  결정과 연결되는지를 내 말로 쓴 것만 남긴다.** 퀴즈 스킬이 이 노트를 출제 근거로 쓴다.
- `lab/` (01·02) — **이론과 짝지어 돌려 보는 실습 코드.** GPU도 실제 사진도 필요 없다.
  - `01-recsys/lab/` — 설계안 §3-B 점수식 전체(BT → λ·conf → 커버리지·MMR)와 §6 평가를
    합성 데이터로 관통시킨다.
  - `02-ml-stats/lab/` — 두 덩어리다. step1~6은 **01이 만든 숫자를 판정하고**(커버리지·
    편향분산·경험적 베이즈·승자의 저주·다중 비교), step7~9는 **A 배치의 분류 문제**를
    다룬다(눈감김 검출·VLM 태그 혼동행렬·확률 보정).
  - `00-models/lab/` — **스파이크 하네스의 진짜 러너를 실제 사진에 돌린다.**
    학습용 흉내가 아니라 `photoselect/scripts/spike/runners/`를 그대로 부른다.
    (venv가 다르다 — `00-models/README.md` 참조)

## 진입 순서 — 난이도 기준 (2026-08-25 정리)

영역 번호는 **논리 순서**이지 난이도 순서가 아니다. 특히 02는 편차가 커서
step 번호대로 들어가면 두 번째 스텝에서 막힌다. 아래가 실제로 밟을 순서다.

### 0단계 — 기초 (처음이면 여기부터, 1~2일)

```
basics/A→E        벡터·코사인 / λ의 출처 / 학습과 BT / nDCG·MMR / 모델 입출력
                  각 파일의 손계산 과제와 자가 점검을 통과하면 1단계로
```

### 1단계 — 감각 잡기 (수식 없음)

```
00-models          모델을 만져 본다. catalog.md 한 번 훑고 lab/step1·2 실행
01 step1           Bradley-Terry = 로지스틱 회귀. 우리가 유일하게 학습시키는 모델
02 step7           분류 지표 — 혼동행렬·정밀도/재현율 (소재: A-1 눈감김)
02 step2           편향-분산·학습 곡선 — "쌍을 더 받을까, 피처를 바꿀까"
```

### 2단계 — 우리 점수식 (01 본체)

```
01 step2 → step3 → step4 → step6        피처·λ·MMR·파이프라인
02 step8                                 혼동행렬 다중 클래스 (VLM 태그 읽는 법)
```

### 3단계 — 실험을 설계하고 판정하기

```
01 step5           검정력·표본 수 — W1–2 실험 설계에 직결
02 step1           커버리지 — 왜 Wilson인가
02 step5           다중 비교 — 여러 지표를 함께 볼 때
02 step6           리포트 한 장
```

### 4단계 — 나중에 (W5 이후여도 된다)

```
02 step3           경험적 베이즈 — 이 영역에서 가장 어렵다. λ의 k를 데이터에서
02 step4           승자의 저주 — 하이퍼파라미터를 고를 때 다시 온다
02 step9           확률 보정 — 이유 문장을 만들 때 다시 온다
```

> **막히면 4단계를 통째로 건너뛰어도 된다.** 1~3단계만으로 W1–2 실험을 설계하고
> 해석할 수 있다. 4단계는 "왜 그 상수인가"를 따질 때 필요해지는 것들이다.

## 학습 순서 (프로젝트 일정 연동)

| 시기 | 학습 | 프로젝트 연결 |
|---|---|---|
| **지금** | **00 모델 카탈로그 (반나절)** | 나머지 전부의 전제 |
| 지금~W2 | 01 추천 시스템 (**자료 + `lab/` 실습 병행**) + 02 중 위 1~3단계 | W1–2 트랙 B 쌍 비교 실험 설계·해석 |
| W1~W3 병행 | 05 GPU 메모리 계산 + vLLM 문서 | 트랙 A 12B/31B 비교 실험 |
| W3~W6 | 03 임베딩 원리 + 04 VLM 구조 개요 | 파이프라인 구현 병행 |
| W5 이후 | 02 4단계 (경험적 베이즈·승자의 저주·보정) | λ 튜닝과 지표 해석 |

## 학습-검증 사이클

1. `materials.md`의 학습 순서대로 자료를 읽는다
2. 짝지어진 `lab/stepN_*.py`를 **직접 실행하고 변형 과제까지 해 본다** (읽기 5 : 돌려보기 5)
3. 배운 것을 `notes.md`에 내 언어로 정리한다 (설계안과의 연결 + 실습에서 본 숫자)
4. `/study-quiz <영역>` 으로 검증받는다 — 결과는 `progress.md`, 틀린 것은 `review-queue.md`로
5. 다음 세션 시작 시 `/study-quiz review` 로 복습 큐부터 소화한다

실습이 만들어 낸 발견은 학습으로 끝내지 않고 **설계 문서에 되먹인다** —
현재 되먹일 목록은 `01-recsys/lab/README.md` 맨 아래 "이 실습이 설계안에 되먹인 것".

상세 규칙과 스킬 설계는 `plan.md` 참조.
