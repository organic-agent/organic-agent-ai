# E. 표현학습·VLM — 블랙박스의 입출력 명세만

## 왜 필요한가

우리는 이 모델들을 **만들지 않는다.** 갖다 쓴다. 그러니 내부(트랜스포머·어텐션)는
후순위이고, 필요한 건 세 가지: **무엇을 넣으면 무엇이 나오나, 그 출력의 성질은
무엇인가, 그래서 어디에 못 쓰나.** 냉장고를 쓰려고 컴프레서 원리를 알 필요는 없지만
"뜨거운 걸 바로 넣으면 안 된다"는 알아야 하는 것과 같다.

---

## 0. 표현학습이란

A에서 "사진을 768개 숫자로 요약"한다고 했다. 그 숫자 만드는 법을 사람이 짜지 않고
**모델이 대량 데이터에서 스스로 배운 것**이 표현학습(representation learning).
"표현" = 벡터, "학습" = 좋은 벡터 만드는 법을 배움. 어떤 데이터로 어떻게 배웠느냐에
따라 벡터가 담는 것이 달라지고, 그게 아래 세 모델의 차이다.

## 1. DINOv2 — 이미지 → 고정 길이 벡터

| | |
|---|---|
| 입력 | 이미지 1장 |
| 출력 | 768차원 벡터 (모델 크기에 따라 384/768/1024) |
| 배운 방식 | **자기지도학습** — 라벨 없이, 같은 사진의 다른 부분/변형이 비슷한 벡터가 되게 |
| 잘하는 것 | 시각적 구조·구도·질감이 비슷한 사진을 가까이 놓음 |
| 못하는 것 | 텍스트와 무관. "이 벡터가 '역광'인가"를 직접 물을 수 없음 |

**비유 — 라벨 없이 사진을 분류한 사람.** 이름은 몰라도 "이 둘은 같은 종류"를 정확히
안다. 우리 용도: 중복/유사 컷 클러스터링, 취향 모델의 입력 x, MMR 유사도.
"라벨 없이 학습됐다"가 중요한 이유 — 웨딩 사진 라벨 데이터가 없어도 그대로 쓸 수 있다.

## 2. CLIP 계열 — 이미지와 텍스트를 같은 공간에

| | |
|---|---|
| 입력 | 이미지 **또는** 텍스트 |
| 출력 | 둘 다 같은 차원의 벡터(예: 512) — 같은 공간 |
| 배운 방식 | **대조학습** — 웹의 (이미지, 캡션) 수억 쌍. 짝은 가깝게, 남은 멀게 |
| 잘하는 것 | "역광 실루엣"이라는 문장 벡터와 사진 벡터의 코사인 → 텍스트로 사진 검색 |
| 못하는 것 | 세부 시각 구조는 DINOv2보다 약함. 캡션에 없던 개념은 모름 |

**비유 — 한영 사전을 하나의 공간에 편 것.** "개"라는 단어와 개 사진이 같은 자리에
놓인다. 우리 용도: LAION 미학 점수(CLIP 벡터 위에 얹은 작은 점수기)가 사진학 prior의
한 축. 미래에 자연어 피드백("어두운 거 빼줘")을 사진 검색으로 바꿀 때의 후보.

**DINOv2와 CLIP 둘 다 쓰는 이유**: DINOv2 = 시각 구조(비슷하게 생겼나), CLIP = 의미
(무엇에 관한 사진인가). 중복 판정엔 전자, 사람 말과 잇는 데엔 후자.

## 3. VLM (Qwen2.5-VL, Gemma 3 등) — 이미지 → 텍스트 생성

| | |
|---|---|
| 입력 | 이미지 + 지시문(프롬프트) |
| 출력 | **텍스트** (문장·JSON·단어) — 한 글자씩 생성 |
| 구조 | 이미지 인코더(CLIP류) + 연결기 + 언어모델(LLM). "사진을 보는 챗봇" |
| 잘하는 것 | "이 사진의 장면은? 표정은? 구도는?" 같은 질문에 말로 답함 |
| 성질 | **확률적 생성** — 같은 사진에 다른 답이 나올 수 있고, 시키지 않은 형식으로 나올 수 있음 |

우리 용도: 5축 고정 태그(장면·인물 구성·표정·구도·조명 등) + 한 줄 캡션.
이 태그가 커버리지의 근거, 이유 문장의 재료, 사진학 prior의 규칙 입력이 된다.

### 백엔드 관점의 핵심 — "확률적 생성"이 만드는 문제와 대응

VLM에 "장면을 골라라: 입장/행진/케이크컷/야외/기타"라고 해도, 그냥 두면
`"신부 입장 장면입니다"`, `"입장 (아마도)"`, `"Entrance"` 처럼 나온다. DB에는 enum
5개 중 하나만 들어가야 한다. 대응은 두 겹:

1. **enum 강제(구조화 출력)** — vLLM의 structured outputs. 생성 단계에서 허용된
   단어 외의 글자를 아예 못 뽑게 막는다. 문법적으로 "입장|행진|케이크컷|야외|기타"만
   가능하게.
2. **검증 로직** — 그래도 코드에서 파싱·검증하고 실패 시 `기타`로 폴백, 실패율을
   기록한다. 모델을 믿지 않는 것이 기본 자세.

이건 "VLM이 똑똑하지 않아서"가 아니라 **출력 형식이 자유 텍스트라는 성질** 때문이다.
DINOv2는 항상 정확히 768개 숫자를 뱉으니 이런 문제가 없다.

## 4. 세 모델 한 표

| 모델 | 입력 | 출력 | 결정적인가 | 우리 역할 |
|---|---|---|---|---|
| DINOv2 | 이미지 | 768 벡터 | 예 | 클러스터·취향 입력·MMR |
| CLIP(+LAION) | 이미지/텍스트 | 512 벡터 → 미학 점수 | 예 | 사진학 prior 한 축, 텍스트 검색 후보 |
| VLM | 이미지+프롬프트 | 텍스트 | **아니오** | 5축 태그·캡션 (enum 강제+검증 필수) |
| (참고) Bedrock LLM | 텍스트 | 텍스트 | 아니오 | 이유 문장·피드백 번역. **이미지 안 보냄** |

마지막 줄이 원가·데이터 원칙의 근거: 이미지를 보는 모델(위 3개)은 전부 자체 GPU,
텍스트만 보는 Bedrock은 이미지를 받을 일이 없다.

## 손계산(사고) 과제

1. 부부가 "사진 12번이랑 비슷한 거 더 보여줘"라고 했다. 세 모델 중 무엇을 쓰나? (DINOv2)
2. "역광 실루엣 사진만 모아줘"라고 했다. 무엇을 쓰나, 두 가지 경로를 말하라.
   (CLIP 텍스트 검색 / VLM 조명 태그 = 역광 필터)
3. VLM이 1,000장 중 30장에 enum 밖의 답을 냈다. 파이프라인은 어떻게 해야 하고,
   이 30이라는 숫자는 어디에 남겨야 하나?
