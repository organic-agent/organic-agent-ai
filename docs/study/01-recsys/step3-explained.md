## 0. STEP 2가 남긴 두 개의 구멍

STEP 2의 마지막 표는 이렇게 끝났다.

```
① 증거가 적을 때 취향을 얼마나 믿을 것인가       →  λ = f(evidence)
② 축마다 증거량이 다른데 어떻게 차등할 것인가     →  conf(axis)
```

그리고 근거가 되는 관찰이 둘 있었다.

| STEP 2의 관찰 | 숫자 |
|---|---|
| 12쌍 × 태그 33차원의 홀드아웃 정확도 | **0.484 ± 0.09** (우연 0.500, 천장 0.662) |
| 쌍이 8개일 때 사진학 2열을 붙여 얻는 이득 | **+0.089** |
| 의견 없는 축(framing)의 추정 상관 | **−0.68** (정답 자체가 노이즈인데 계수는 0이 아님) |

**요약하면 이렇다.** 취향 추정은 초반에 거의 잡음이다. 그런데 사진학 점수는 개인화는
못 해도 크게 틀리지 않는다. 그러면 **둘을 섞되, 섞는 비율을 증거량에 따라 움직이면 된다.**
이게 설계안 §3-B의 점수식이다.

```
score(p) = (1−λ)·prior(p)  +  λ·pref(p)  + coverage − mmr
             └─사진학─┘        └─취향─┘
λ = f(증거 수)
pref(p) = Σ_axis conf(axis)·P(tag_axis(p) | 선호분포) + β·max_sim(p, 선호벡터)
                 └────────┘
```

STEP 3에서 만들 것은 앞쪽 두 항, **λ와 conf(axis)** 다. 뒤의 coverage·mmr은 step4.

### 이번 실습의 세계

```
갤러리 1000장 · 가상 고객 12명 · 취향 세기 1.5 · 변덕 temp=0.7
설계 규칙 후보 쌍 771개 → 학습용 386 / 홀드아웃 385
평가 지표: 상위 30장의 평균 '만족도'
```

**만족도의 정의를 먼저 봐야 한다.** step1·step2는 쌍 정확도로 평가했는데, 여기서는
"추천 30장이 좋았는가"를 재야 하므로 정답 만족도를 이렇게 정의했다.

```python
satisfaction = z(취향 효용) + 0.5 · z(사진학 점수)
```

> **왜 취향만으로 평가하지 않는가.**
> 취향만을 정답으로 두면 실험은 자동으로 "λ=1이 최고"라고 답한다. 물어보나 마나다.
> 실제 고객은 취향에 맞아도 흔들린 사진을 담지 않는다 — **사진학 품질도 만족의 일부**다.
> 그 비중(0.5)은 우리가 정한 가정이고, 이 실습의 모든 λ 결론은 **그 가정 위에 있다.**
> `QUALITY_WEIGHT`를 0.2나 1.0으로 바꾸면 최적 λ가 움직인다. 반드시 한 번 해 볼 것.

이건 실습의 한계가 아니라 **평가 설계의 본질**이다. 실전에서도 "무엇을 좋다고 할 것인가"를
먼저 정하지 않으면 λ를 튜닝할 수 없다. 우리 설계에서 그 자리를 채울 것이 수락률·후회율이다(step5).

## 1. λ — 두 점수 사이의 베팅 비율

### 왜 하필 '섞기'인가

선택지는 셋이었다.

| 방법 | 문제 |
|---|---|
| 취향만 쓴다 | 12쌍짜리 잡음에 전부를 건다. 실패 모드는 [D]에서 본다 |
| 사진학만 쓴다 | 개인화가 없다. 모든 부부에게 같은 30장 → "AI 셀렉터"라고 부를 수 없다 |
| **품질로 거르고 취향으로 순위** | **하드 필터링이라 금지** (CLAUDE.md: 품질 점수로 하드 필터링 금지) |

세 번째가 특히 매력적으로 보이는데 안 되는 이유가 있다. 품질 하위 30%를 잘라 내면
**부부에게 의미 있는 한 장**(흔들렸지만 아버지가 우는 컷)이 후보에서 사라진다.
점수는 순위를 흔들 뿐 후보를 없애면 안 된다. 그래서 **가중 합**이다.

### λ = f(n)의 꼴은 베이지안에서 빌려 온다

베이지안 사후평균은 이렇게 생겼다.

```
사후평균 = (n/(n+k))·데이터평균 + (k/(n+k))·사전평균
```

`k`는 **"사전분포가 데이터 몇 개만큼의 힘을 갖는가"** 다(가상 표본 크기).
데이터가 k개 쌓이면 데이터와 사전이 반반이 된다. λ도 같은 꼴로 쓴다.

```
λ(n) = λ_min + (λ_max − λ_min) · n/(n+k)
```

설계안의 명세("증거 0개 → 약 0.2, 12쌍+별점 20개(=32) → 약 0.7, 상한 있음")에 맞추면
`λ_min=0.2, λ_max=0.85, k=10`이다. 손으로 확인해 보면:

```
λ(0)  = 0.2 + 0.65 · 0/10   = 0.20   ✓ 명세 0.2
λ(32) = 0.2 + 0.65 · 32/42  = 0.695  ✓ 명세 0.7
λ(12) = 0.2 + 0.65 · 12/22  = 0.55
```

> **여기서 사진학 prior가 곧 사전분포다.** "이 부부에 대해 아무것도 모를 때의 최선의 추측".
> λ는 그 사전분포를 얼마나 빨리 놓아줄 것인가의 문제다. STEP 2에서 L2 정규화가
> "w는 0 근처일 것"이라는 사전분포였던 것과 **완전히 같은 사상**이다. 층이 다를 뿐이다.

### 스케일을 맞추지 않으면 λ는 아무 의미가 없다

`prior`는 백분위(0~100)이고 `pref`는 로지스틱 계수의 내적(대략 −3~3)이다.
이대로 `0.5·prior + 0.5·pref`를 하면 prior가 100% 이기고 λ는 장식이 된다.

**갤러리 안에서 각각 z-표준화한 뒤 섞는다.**

```python
def z(v):
    return (v - v.mean()) / v.std()
```

이 한 줄이 없으면 λ의 모든 숫자가 거짓말이 된다. 그리고 이 z-표준화가
**나중에 conf의 효과를 절반 지운다** — [C]에서 본다.

## 2. [실험 A] λ 곡선 — 상한이 왜 필요한가

```
증거   0개 → λ=0.20  ████████
증거   4개 → λ=0.39  ███████████████
증거   8개 → λ=0.49  ████████████████████
증거  12개 → λ=0.55  ██████████████████████
증거  20개 → λ=0.63  █████████████████████████
증거  32개 → λ=0.70  ████████████████████████████
증거  60개 → λ=0.76  ██████████████████████████████
증거 200개 → λ=0.82  █████████████████████████████████
```

읽을 것은 두 가지다.

**① 처음에는 사진학이 80%를 쥔다.** 온보딩을 아직 안 한 부부에게도 초안은 나가야 한다.
그때 나가는 것은 사실상 "잘 찍힌 사진 30장"이다. 그게 맞다 — 아무 증거도 없는데
개인화하는 척하는 것이 더 나쁘다.

**② 증거가 아무리 쌓여도 0.85에서 멈춘다.** 상한이 없으면 어떻게 되나:

```
λ → 1  ⇒  score = pref  ⇒  사진학 가중이 0
```

**"취향에는 맞지만 눈 감고 흔들린 사진"** 이 상위에 올라온다. 200쌍을 받아도
사진 품질은 여전히 만족의 일부다(§0의 만족도 정의). 상한은 그 몫을 최소한 15% 남겨 두는 장치다.

> 이건 CLAUDE.md의 **"품질 점수로 하드 필터링 금지"** 와 짝을 이룬다.
> 아래로도(필터링 금지) 위로도(λ 상한) 품질 점수의 권한을 제한한다.
> 품질은 **순위를 흔드는 힘이지 결정권이 아니다.**

## 3. [실험 B] 고정 λ 하나로는 두 구간을 못 덮는다

### 결과

상위 30장의 평균 만족도. 클수록 좋다. (고객 12명 평균)

```
증거(쌍)      λ=0    λ=0.2   λ=0.4   λ=0.6   λ=0.8    λ=1     λ=f(n)
  0        0.976   0.976   0.976   0.976   0.976   0.014    0.976
  4        0.976   1.038   1.012   0.907   0.721   0.373    1.025
 12        0.976   1.208   1.329   1.276   1.009   0.582    1.295
 30        0.976   1.200   1.240   1.312   1.173   0.846    1.286
100        0.976   1.380   1.624   1.766   1.732   1.446    1.724
300        0.976   1.481   1.824   1.980   1.982   1.645    1.969
```

### ① 0쌍 · λ=1의 0.014를 먼저 봐야 한다

증거가 하나도 없으면 `pref`는 전부 0이다. λ=1이면 score도 전부 0 →
**순위가 아무 의미 없는 30장**이 나간다. 만족도 0.014 = 갤러리 평균.

> 이 칸이 이 표에서 가장 중요한 칸이다. **λ가 "얼마나 개인화할까"의 다이얼이 아니라
> "증거 없이도 뭔가 내놓아야 하는 상황을 어떻게 버틸까"의 장치**라는 걸 보여 준다.
> 0.976(λ=0)과 0.014(λ=1)의 차이가 λ_min이 존재하는 이유 전부다.

### ② 어느 고정 λ도 전 구간에서 이기지 못한다

행마다 최댓값이 어디 있는지 표시해 보면:

| 증거 | 최적 λ | 그 값 | λ=0.2로 고정하면 | λ=0.8로 고정하면 |
|---|---|---|---|---|
| 4쌍 | **0.2** | 1.038 | 1.038 | 0.721 (−30%) |
| 12쌍 | **0.4** | 1.329 | 1.208 | 1.009 |
| 100쌍 | **0.6** | 1.766 | 1.380 (−22%) | 1.732 |
| 300쌍 | **0.8** | 1.982 | 1.481 (−25%) | 1.982 |

**λ=0.2로 고정하면 후반에 22~25% 손해, λ=0.8로 고정하면 초반에 30% 손해다.**
최적점이 증거량과 함께 오른쪽으로 움직인다 — 그래서 λ를 상수가 아니라 함수로 둔다.
설계안의 `λ = f(evidence)`가 여기서 실험적으로 정당화된다.

### ③ 설계 곡선의 성적 — 그리고 곡선이 살짝 공격적이라는 신호

마지막 열이 `λ = f(n)` 곡선을 그대로 썼을 때다. 각 행의 최댓값과 비교하면:

| 증거 | 최댓값 | 설계 곡선 | 곡선이 쓴 λ | 달성률 |
|---|---|---|---|---|
| 4쌍 | 1.038 (λ=0.2) | 1.025 | 0.39 | 98.7% |
| 12쌍 | 1.329 (λ=0.4) | 1.295 | 0.55 | 97.4% |
| 100쌍 | 1.766 (λ=0.6) | 1.724 | 0.79 | 97.6% |
| 300쌍 | 1.982 (λ=0.8) | 1.969 | 0.83 | 99.3% |

**달성률은 97~99%로 충분히 좋다.** 다만 눈여겨볼 것이 있다 —
**곡선이 쓴 λ가 매번 최적 λ보다 위에 있다.** 4쌍에서 0.39 vs 0.2, 100쌍에서 0.79 vs 0.6.

곡선이 **일관되게 취향 쪽으로 조금 기울어 있다**는 뜻이다. 손해가 크지 않아 지금
고칠 일은 아니지만, 원인 후보는 둘이다.

- `k=10`이 작다 → 증거를 실제보다 세게 쳐 준다
- `λ_max=0.85`가 높다

**변형 과제 1**: `LAMBDA_K`를 3과 30으로 바꿔 이 표를 다시 뽑아 보라.
k=30이면 곡선이 어느 행에서 최댓값에 더 붙는가? 이게 곧 λ 곡선 튜닝이다.
그리고 [E]를 읽고 나면 **k를 지금 확정하면 안 되는 이유**를 알게 된다.

## 4. [실험 C] conf(axis) — 축마다 다르게 믿기

### 왜 축별 차등이 필요한가

STEP 2 실험 D에서 본 것: 사람 #0은 `expression`·`subjects`에만 의견이 있고
`framing`에는 없다(진짜 취향의 표준편차 0.077). 그런데 **모델은 그걸 모른다.**
`w_hat`의 framing 계수는 어쨌든 0이 아닌 값이 나오고, 그대로 쓰면
**없는 취향으로 사진 순위를 흔든다.**

여기에 두 번째 사정이 겹친다. **축마다 증거량 자체가 다르다.** 12쌍 중
framing이 갈린 쌍이 6개인데 lighting은 1개일 수 있다. 쌍 규칙이 "한 축만 다름"이므로
12쌍은 5개 축에 흩어진다.

### 베타-이항 사후평균으로 누른다

```
p̂_axis = (그 축에서 추정 방향이 맞은 쌍 수 + a) / (그 축이 갈린 쌍 수 + 2a)
conf    = max(0, 2·p̂ − 1)
```

`a`는 사전 강도(실습은 1.0). 손으로 몇 개 계산해 보면 감이 온다.

| 그 축이 갈린 쌍 | 맞은 쌍 | p̂ | conf | 해석 |
|---|---|---|---|---|
| 0 | – | 0.5 | **0.00** | 물어본 적 없다 → 기여 없음 |
| 1 | 1 | (1+1)/(1+2)=0.667 | 0.33 | 한 번 맞았다고 다 믿진 않는다 |
| 2 | 2 | (2+1)/(2+2)=0.750 | 0.50 | |
| 6 | 6 | (6+1)/(6+2)=0.875 | 0.75 | 증거가 쌓이면 올라간다 |
| 6 | 3 | (3+1)/(6+2)=0.500 | **0.00** | **50:50이면 0** — 설계안 명세 그대로 |

`conf = max(0, 2p̂−1)`의 꼴을 보라. p̂=0.5(=동전 던지기)면 정확히 0이 된다.
**"이 사람이 이 축에 의견이 있는가"를 재는 장치**다.

### 실행 결과 — conf가 자라는 것을 본다

```
증거(쌍)      conf 없음    conf 적용   |  축별 conf 평균
  4          0.996       1.025      |  scen 0.00  fram 0.42  ligh 0.42  expr 0.15  subj 0.03
 12          1.282       1.295      |  scen 0.00  fram 0.48  ligh 0.43  expr 0.49  subj 0.19
 30          1.212       1.286      |  scen 0.00  fram 0.43  ligh 0.46  expr 0.51  subj 0.47
100          1.611       1.724      |  scen 0.00  fram 0.46  ligh 0.33  expr 0.49  subj 0.69
```

**① `scene`은 언제나 정확히 0이다.** 우연이 아니다. 쌍 규칙이 "같은 scene끼리만 비교"라
scene이 갈린 쌍이 **구조적으로 0개**다(step2 [D]). 그러면 p̂=0.5 → conf=0.
설계안의 "증거 없는 축은 점수에 기여하지 않는다"가 문자 그대로 일어난다.

> **이게 conf의 진짜 값어치다.** scene 계수를 실수로 쓰는 사고가 원천 차단된다.
> 그리고 그 공백을 메우는 것이 장면 커버리지다 — step4의 주제이자,
> 08-25 실측이 흔든 바로 그 지점이다(§6과 `step2-explained.md` §5.5).

**② `subjects`가 0.03 → 0.19 → 0.47 → 0.69으로 자란다.** 베타-이항 shrinkage가
증거량에 따라 풀리는 과정을 그대로 본다. 4쌍에서 0.03이면 그 축은 사실상 꺼져 있다.

**③ 4쌍인데 framing conf가 0.42인 것은 좀 후하다.** 위 손계산에서 봤듯 갈린 쌍 1개를
맞히기만 해도 0.33이 나온다. `a=1`이 약한 사전이라는 뜻이다.

**변형 과제 2**: `axis_confidence`의 `a`를 3.0으로 올려 보라. 4쌍 행의 conf가
얼마나 내려가고, 만족도는 어떻게 되는가? (`a`는 "몇 쌍쯤 봐야 이 축을 믿을까"의 다이얼이다)

### 왜 이득이 이렇게 작은가 — z-표준화가 절반을 지운다

conf를 켠 이득은 4쌍에서 +0.029, 100쌍에서 +0.113이다. **방향은 맞는데 폭이 작다.**
이유가 있다.

```python
pref = z(pref_scores(g, w_hat, conf))    # ← conf를 곱한 뒤 다시 z-표준화한다
```

conf를 모든 축에 곱하면 pref 벡터 전체가 작아진다. 그런데 그 뒤에 z-표준화를 하므로
**"전체를 줄이는" 성분은 통째로 상쇄된다.** 살아남는 것은 **축 사이의 상대 가중**뿐이다.

> **그래서 λ와 conf는 겹치지 않는다.**
>
> | 장치 | 하는 일 | 지워지는가 |
> |---|---|---|
> | **λ** | 취향 전체 vs 사진학 — **전역 축소** | 안 지워진다 (prior와 섞기 전이므로) |
> | **conf** | 축 A vs 축 B — **축 간 차등** | 전역 성분만 지워진다 |
>
> 둘 다 "덜 믿는다"인데 **누구에 대해 덜 믿는가**가 다르다.
> 만약 z-표준화를 빼고 conf의 전역 축소를 살려 두면 λ와 이중으로 눌려
> 취향이 사라진다. 설계안이 λ와 conf를 분리해 둔 이유가 이것이다.

### 실무 규칙 — 이유 문장은 conf가 보증한다

`pref`에 쓰는 것과 **부부에게 문장으로 말하는 것**은 기준이 달라야 한다.

```
"클로즈업을 선호하셔서 이 컷을 골랐어요"   ← framing conf가 충분히 높을 때만
```

conf 0.42는 순위를 조금 흔들기에는 충분해도 **단언하기에는 부족하다.**
아니라고 느낀 부부는 "우리가 언제 그랬지?"에서 추천 전체의 신뢰를 잃는다.
설계안이 이유 문장을 LLM에 맡기면서도 **소재를 점수 파이프라인이 정하게** 한 이유다.

### ※ 이 표를 확정으로 읽지 말 것

conf 이득 폭(+0.029 ~ +0.113)은 작다. 고객 12명 한 번 돌린 값이다.
`N_PERSONS`와 seed를 바꿔 **방향이 유지되는지** 확인해야 한다.
한 번 돌린 숫자로 설계를 확정하지 않는 습관 — 그게 step5의 내용이다.

## 5. [실험 D] 실패 모드 — λ=1이면 무엇이 무너지나

12쌍만 받고 λ=1(취향만)로 상위 30장을 뽑았을 때, 고객 #0:

```
λ=1    (취향만)     framing 분포 [half:30]                          장면 8종 · 최저 품질 백분위  1
λ=0.55 (설계 곡선)  framing 분포 [half:29 wide:1]                   장면 9종 · 최저 품질 백분위 67
λ=0    (사진학만)   framing 분포 [closeup:13 half:12 full:3 wide:2] 장면 6종 · 최저 품질 백분위 88
```

세 가지가 한꺼번에 보인다.

**① 한 축으로 쏠린다.** 30장이 전부 `framing=half`다. 12쌍짜리 추정이 half에 살짝
유리하게 나왔을 뿐인데, 그 미세한 차이가 상위 30장을 싹쓸이한다.
**순위 기반 추천의 구조적 성질**이다 — 점수 차가 아무리 작아도 정렬은 이분법처럼 작동한다.

**② 최저 품질 백분위가 1이다.** 갤러리에서 가장 못 찍힌 축에 드는 사진이 초안에 들어간다.
부부가 초안을 열고 처음 보는 것이 흔들린 사진이면, 나머지 29장이 아무리 좋아도
"이 AI 별로네"가 된다. **첫인상은 최악의 한 장이 정한다.**

**③ 장면 종류 수는 λ로 해결되지 않는다.** λ=1이 8종, λ=0이 6종 — 오히려 λ=1이 많다.
장면 다양성은 λ가 다루는 문제가 아니다. 여기가 **커버리지와 MMR이 필요한 자리**다(step4).

> **λ가 고치는 실패와 못 고치는 실패를 구분해서 외울 것.**
> 고친다: 잡음 추정에 올인 → 쏠림·저품질 유입
> 못 고친다: 다양성 부족·근접 중복 → 커버리지·MMR의 일

## 6. [실험 E] 태그가 틀릴 때 — 2026-08-25 VLM 실측 반영

### 실습의 숨은 가정이 하나 깨졌다

[A]~[D]는 전부 **"VLM 태그가 100% 맞다"** 는 가정 위에 있었다. `gallery.py`에서
`X`는 학습 피처이면서 동시에 사람의 효용을 만드는 정답이었기 때문이다.

2026-08-25 VLM 1차 실측(`photoselect/docs/spike-report.md`)은 그렇지 않다고 말한다.

| 축 | scene | lighting | expression | framing | subjects |
|---|---|---|---|---|---|
| 정확도 | **74%** | 84% | 90% | 92% | 98% |

(gemma3:12b 4bit 로컬 · 50장 사람 전수 채점. **4bit 하한**이라 프로덕션 FP16은 이보다 낫다)

그래서 `gallery.py`에 태그를 두 벌로 갈랐다. 기본값은 `tag_error=0`이라
**[A]~[D]와 step1·step2의 모든 숫자는 그대로 재현된다.** 오차는 실험에서만 켠다.

| | 정체 | 누가 쓰나 |
|---|---|---|
| `tags` / `X` | VLM이 뱉은 **관측** 태그 | 쌍 규칙 판정, 취향 학습, 커버리지 — 파이프라인 전부 |
| `tags_true` / `X_true` | 사진의 **실제** 내용 | 사람의 효용, 사진학 점수, 임베딩 |

오차는 실측된 **방향**까지 흉내낸다. 08-25 오답은 두 축 모두 한 방향이었다.

- `lighting` — 정답 `indoor`를 `natural`로 (8건 중 8건, 예외 없음)
- `scene` — 정답 `snap`을 예식 장면으로 과잉 분류 (13건 **전부** 정답이 snap)

> **조건부 확률로 넣는다는 것이 중요하다.** 실측 "scene 74%"는 snap이 68%인 표본에서
> 나온 값이라 그대로 쓰면 장면 분포가 다른 갤러리에서 뜻이 달라진다. 모델은
> `P(오답 | 정답=snap) = 13/34 = 0.38`을 쓰고, 전체 오답률은 갤러리 분포가 정한다 —
> 이 갤러리(snap 27%)에서는 10%, `scene_profile="measured"`(snap 68%)에서는 24%다.
> **초기 구현은 전체 오답률 26%를 맞추도록 짰다가 snap의 96%를 오분류하는 사고가 났다.**
> 02 step8(혼동행렬)에서 그 버그가 잡혔다 — 스칼라 오답률만 보면 안 보이는 종류의 오류다.

### ① 쌍 규칙이 태그 오차만큼 샌다

```
후보 풀 771쌍(정답 태그)  →  656쌍(관측 태그)
그 656쌍 중 정답 태그로도 규칙을 만족하는 것: 441쌍 (67%)
```

**33%는 실제로는 장면이 다르거나 두 축 이상 다른 쌍이다.**

STEP 2 §4의 결론은 "설계 규칙이 교란변수를 제거한다"였다. 그건 태그가 맞을 때의 얘기다.
규칙 판정은 정답이 아니라 **VLM이 적어 준 태그로 할 수밖에 없고**,
하필 **가장 부정확한 축(`scene`)이 규칙의 첫 조건**이다.

> 랜덤 쌍과 질적으로 다른 건 맞다(랜덤 쌍은 품질 백분위 차 중앙값 29.8 vs 설계 쌍 7.3).
> 다만 **정도의 차이지 성질이 다른 게 아니다.** "우리 쌍은 교란변수가 없다"고
> 멘토에게 말하면 반례가 이것이다.

### ② 최적 λ가 초반 구간에서 내려간다

```
                        λ=0    λ=0.2   λ=0.4   λ=0.6   λ=0.8    λ=1    최적λ   설계곡선
12쌍 · 태그 완벽       0.976   1.208   1.329   1.276   1.009   0.582    0.4     1.295
12쌍 · 태그 실측오차   0.976   1.072   0.983   0.891   0.671   0.211   *0.2*    0.948
100쌍 · 태그 완벽      0.976   1.380   1.624   1.766   1.732   1.446    0.6     1.724
100쌍 · 태그 실측오차  0.976   1.245   1.425   1.544   1.529   1.158    0.6     1.524
```

**12쌍에서 최적 λ가 0.4 → 0.2로 내려간다.** 설계 곡선은 λ(12)=0.55를 쓰므로
최적점에서 두 칸 위다(만족도 0.948 vs 1.072, −12%).

**100쌍에서는 최적점이 0.6 그대로다.** 양이 쌓이면 태그 오차를 견딘다.
흔들리는 것은 **증거가 적은 초반 구간**뿐이다 — 그런데 온보딩 12쌍이 정확히 그 구간이다.

> **λ = f(n)은 증거의 '양'만 본다. 그런데 증거의 '질'도 λ를 움직인다.**
>
> 이건 통계에서 잘 알려진 현상이다. 피처에 측정 오차가 있으면 회귀계수가
> 0 쪽으로 축소되고(attenuation), 추정의 분산은 커진다. 즉 **같은 쌍 수라도
> 태그가 흐리면 pref는 더 못 믿을 것이 된다.** λ가 그만큼 내려가야 한다.

**되먹임**: `λ_K = 10`은 **태그 정확도가 확정되기 전에는 확정할 수 없다.**
(그리고 02 step3 [D]가 그 k를 데이터에서 추정하는 방법과, 측정값이 **114**라는 것을 보여 준다)

### ③ conf에 축 신뢰도를 곱하면? — 그럴듯한데 안 먹힌다

```
증거(쌍)      conf만     conf×신뢰도
 12          0.948        0.946      (−0.002)
100          1.524        1.518      (−0.006)
```

**차이가 없다.** 이유는 둘이다.

**(a) z-표준화가 또 지운다.** §4에서 본 그대로다. conf에 무엇을 곱하든
"모든 축을 같은 비율로 줄이는" 성분은 상쇄된다.

**(b) conf가 이미 부분적으로 흡수하고 있다.** 태그가 부정확한 축은 추정 방향과
실제 선택이 어긋나는 쌍이 늘어난다 → p̂이 0.5로 내려간다 → conf가 자동으로 내려간다.

> **[C]와 정확히 같은 교훈이다.** 같은 정보를 두 군데서 빼지 않는다.
> 태그 품질은 conf가 아니라 **λ 쪽(=증거의 질)** 이나 **태그 파이프라인 자체**에서 다뤄야 한다.

## 7. 종합 — STEP 3이 설계안의 무엇을 정당화하는가

| 실험 | 관찰 | 설계 결정 |
|---|---|---|
| B ① | 증거 0 · λ=1이면 만족도 0.014 (=무작위) | **λ_min = 0.2** — 증거 없이도 내놓아야 한다 |
| B ② | 최적 λ가 0.2 → 0.8로 이동. 고정 λ는 22~30% 손해 | **λ = f(evidence)** |

| **E ①** | **관측 태그 풀의 33%가 실제로는 규칙 위반** | 쌍 규칙의 한계를 리포트에 명시해야 |
| **E ②** | **태그 오차 시 12쌍 최적 λ 0.4 → 0.2** | **k는 태그 정확도 확정 후에 정한다** |

### 한 줄 정리

> **STEP 2는 "12쌍으로는 못 배운다"를 보였고,
> STEP 3은 "그래도 쓰는 방법"을 만든다 — 얼마나 믿을지를 증거의 양(λ)과
> 축(conf)으로 나눠서 정한다.**
> 그리고 [E]가 세 번째 축을 더한다: **증거의 질(태그 정확도)** 도 λ를 움직인다.

## 8. 남은 질문 → step4

STEP 3이 못 고친 것이 [D]에 그대로 남아 있다.

```
① 상위 30장이 서로 너무 비슷하다 (연사 쌍둥이 컷)   →  MMR
② 특정 장면이 아예 빠진다                          →  장면 커버리지
```

> `make_gallery(scene_profile="measured")`로 step4를 다시 돌려 보면
