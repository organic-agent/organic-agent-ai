## 0. "점수 상위 N장"이 왜 답이 아닌가

추천 시스템 입문에서 가장 늦게 배우는 것이 이것이다. 점수를 잘 만들면 정렬해서
위에서 자르면 될 것 같은데, 실제로는 두 가지가 무너진다.

```
① 상위 30장이 서로 너무 닮았다   →  "다 비슷한데요"          →  MMR
② 특정 장면이 통째로 빠진다      →  "서약 사진이 하나도 없네요" →  장면 커버리지
```

**둘은 다른 문제다.** 그리고 둘 다 점수식으로는 못 고친다 —
점수는 **한 장을 독립적으로** 평가하는데, 이 실패들은 **뽑힌 집합 전체의 성질**이기 때문이다.

> 이 구분이 STEP 4의 전부다. `score(p)`는 사진 p 하나만 보고 계산된다.
> "이미 뽑은 29장과 얼마나 겹치는가"는 p의 성질이 아니라 **목록의 성질**이다.
> 그래서 점수 계산이 끝난 **다음 단계**(재랭킹)가 따로 필요하다.

### 왜 웨딩 갤러리에서 특히 심한가 — 연사(burst)

합성 갤러리의 구조를 재 보면 이렇다.

```
1,000장 → 클러스터 322개 · 평균 3.1장 · 최대 5장

코사인 유사도    같은 클러스터           0.885   ← 사실상 같은 사진
                같은 장면 · 다른 클러스터  0.383
                무관한 두 장             0.017
```

작가는 셔터를 연사로 누른다. 서약 장면 하나에서 5장이 거의 동시에 찍힌다.
**그 5장은 노출·구도·조명이 같으므로 점수도 거의 같다.** 점수 상위 30장을 자르면
쌍둥이가 통째로 딸려 들어온다.

`gallery.py`가 이 구조를 일부러 넣어 둔 이유가 여기 있다.

```python
# 연사 안에서는 노출·구도가 거의 같으므로 클러스터 공통 성분이 크고,
# 개별 차이는 눈 감김 같은 순간의 사고에서 온다.
raw_tech = 0.85 * cl_tech + 0.4 * rng.normal(size=n)
#          └─클러스터 공통─┘   └─개별 차이─┘
```

**클러스터 공통 성분이 개별 차이의 2배다.** 임베딩을 난수로 만들었다면 MMR을 실습해도
아무 일도 일어나지 않는다. 실패를 재현할 수 있어야 대책을 검증할 수 있다.

## 1. MMR — 20줄이면 끝난다

### 식 (Carbonell & Goldstein 1998)

이미 뽑은 집합 S가 있을 때, 다음 한 장을 이렇게 고른다.

```
argmax_{d ∉ S} [ λ·Sim1(d, q) − (1−λ)·max_{s∈S} Sim2(d, s) ]
                  └─얼마나 좋은가─┘      └─이미 뽑은 것과 얼마나 닮았나─┘
```

우리 경우 `Sim1`은 STEP 3에서 만든 `score`이고, `Sim2`는 DINOv2 임베딩의 코사인이다.
`λ_mmr = 1`이면 그냥 상위 N장, 낮을수록 다양성 우선.

> **λ가 두 개다. 헷갈리지 말 것.**
>
> | | 무엇을 섞나 | 어디서 |
> |---|---|---|
> | `λ_score` | 사진학 prior ↔ 취향 pref | STEP 3, 증거량의 함수 |
> | `λ_mmr` | 관련성 ↔ 다양성 | STEP 4, 고정 하이퍼파라미터 |
>
> 이름이 같을 뿐 완전히 다른 다이얼이다. 실습 코드도 `lam`과 `lam_mmr`로 나눠 놨다.

### 구현에서 볼 것 — 왜 O(K·N)인가

```python
max_sim = np.full(len(pool), -np.inf)      # 각 후보의 '이미 뽑힌 것과의 최대 유사도'
for _ in range(k):
    penalty = np.where(np.isfinite(max_sim), max_sim, 0.0)
    mmr = lam * score[pool] - (1 - lam) * penalty
    mmr[~alive] = -np.inf
    pick = int(np.argmax(mmr))
    ...
    sims = emb[pool] @ emb[pool[pick]]     # 새로 뽑힌 것과의 유사도만 계산
    max_sim = np.maximum(max_sim, sims)    # ★ 최대값만 갱신하면 된다
```

**핵심은 `np.maximum` 한 줄이다.** 벌점이 `max_{s∈S}`이므로, 한 장을 새로 뽑을 때마다
"기존 최대"와 "새로 뽑은 것과의 유사도"를 비교해 큰 쪽만 남기면 된다.
S 전체를 다시 훑을 필요가 없다 → 한 장당 O(N), 총 O(K·N).

30장 뽑는 데 1,000×30 = 3만 번의 내적. **pgvector 위에서 수십 줄로 끝난다.**
설계안이 DPP(determinantal point process) 같은 걸 안 쓰는 이유다 — 이걸로 충분하다.

> **첫 반복의 `-inf` 처리에 주의.** S가 비어 있을 때 `max_{s∈S}`는 정의되지 않는다.
> 코드는 `-inf`를 0으로 바꿔 벌점을 없애고, 결국 첫 장은 순수 최고 점수가 뽑힌다.
> 이걸 빼먹으면 `-inf`가 전파돼 전부 `nan`이 된다. 직접 짤 때 가장 흔한 버그다.

## 2. [실험 A] 상위 N장 vs MMR vs 커버리지

증거 30쌍을 받은 상태(λ_score=0.69)에서 30장을 네 가지 방법으로 뽑았다.

```
점수 상위 N장               만족도 +0.799 · ILS 0.110 · 장면 10종 · 클러스터 중복 2장
MMR (λ_mmr=0.9)            만족도 +0.824 · ILS 0.111 · 장면 11종 · 클러스터 중복 2장
MMR (λ_mmr=0.7)            만족도 +0.908 · ILS 0.101 · 장면 11종 · 클러스터 중복 1장
MMR (λ_mmr=0.5)            만족도 +0.937 · ILS 0.092 · 장면 12종 · 클러스터 중복 0장
커버리지 + 클러스터 + MMR     만족도 +0.847 · ILS 0.077 · 장면 12종 · 클러스터 중복 0장
```

**ILS**(intra-list similarity) = 뽑힌 30장 내부 쌍의 평균 코사인. **낮을수록 다양하다.**

### ① 상위 N장에는 쌍둥이가 들어온다

`클러스터 중복 2장` — 30장 중 2장이 이미 뽑힌 것과 같은 연사다.
숫자로는 작아 보이지만 **화면에서는 나란히 붙어 보인다.** 코사인 0.885짜리 두 장이
연속으로 놓이면 고객은 "이거 아까 그거 아니에요?"라고 말한다.

### ② 반직관 — MMR이 만족도까지 올린다

다양성은 보통 **관련성을 희생해서** 얻는 것으로 배운다. 그런데 여기서는
`0.799 → 0.937`로 **같이 올랐다.** 왜?

```
쌍둥이 3장이 상위 30에서 3자리를 먹으면
  → 다른 좋은 클러스터가 통째로 30위 밖으로 밀린다
  → 밀려난 클러스터의 대표 컷이 쌍둥이 2·3번보다 만족도가 높다
```

**연사 구조에서는 중복 제거가 공짜가 아니라 이득이다.** 쌍둥이의 2번째·3번째 장은
1번째와 만족도가 거의 같으므로 **한계 효용이 0에 가깝다.** 그 자리를 다른 클러스터에
주면 새로운 효용이 들어온다.

> 실전 함의: "다양성을 넣으면 정확도가 떨어질 텐데요"라는 반론에
> **"우리 데이터에서는 반대다"** 라고 답할 수 있다. 근거는 연사 구조다.
> 다만 이건 **연사가 많은 갤러리에서만** 참이다. 데이터 구조에 의존하는 주장이다.

### ③ 그런데 '평균 만족도'는 중복을 벌하지 않는다

여기가 이 실험에서 가장 중요한 대목이다.

**30장이 전부 똑같은 컷이어도 평균 만족도는 높을 수 있다.**
평균은 목록 내부의 관계를 전혀 보지 않기 때문이다. 만약 우리가 만족도 하나만 보고
튜닝했다면, 지표가 좋아지는 방향으로 최악의 목록을 만들 수 있었다.

그래서 이 표는 **네 개를 함께** 찍는다.

| 지표 | 잡는 실패 |
|---|---|
| 만족도 | 품질·취향이 나쁜 목록 |
| ILS | 전반적으로 비슷비슷한 목록 |
| 클러스터 중복 | 연사 쌍둥이 |
| 장면 종류 | 특정 장면 누락 |

**지표가 실패 모드를 못 잡으면 알고리즘보다 지표를 먼저 늘려야 한다.** step5의 주제다.

### ④ 커버리지가 만족도에서는 오히려 손해다

`커버리지 + 클러스터 + MMR`의 만족도 `+0.847`은 `MMR(0.5)`의 `+0.937`보다 낮다.
당연하다 — **장면마다 최소 장수를 강제로 채우느라** 점수가 낮은 사진을 넣기 때문이다.

그런데 장면 종류 12종, ILS 0.077로 **둘 다 최고**다. 무엇을 살 것인지의 문제다.
설계안이 커버리지를 **하드 제약**으로 둔 것은 "서약 사진 0장"이
만족도 0.09만큼의 손해보다 훨씬 큰 사고라고 판단한 것이다.

## 3. [실험 B] λ_mmr 다이얼 — 그리고 왜 못 박지 않는가

```
λ_mmr     만족도      ILS    장면 종류   클러스터 중복
1.0      0.799     0.110      10          2
0.9      0.824     0.111      11          2
0.8      0.830     0.103      11          1
0.7      0.908     0.101      11          1
0.5      0.937     0.092      12          0
0.3      0.990     0.084      12          0
0.0     -0.027     0.032      12          0
```

### λ_mmr = 0의 붕괴를 먼저 보라

만족도 `−0.027`. **품질을 완전히 버린 결과다.** λ=0이면 식이 `−max_sim`만 남아
"이미 뽑은 것과 가장 안 닮은 것"만 고른다. 점수가 아예 안 들어간다.

> 게다가 첫 장은 벌점이 전부 0이라 **`argmax`가 그냥 0번 인덱스를 집는다.**
> 즉 λ_mmr=0의 첫 장은 "갤러리에서 아무 사진"이다. 실습에서 극단을 보여 주는 값이지
> 실제로 쓸 수 있는 설정이 아니다.

### ILS가 단조 감소하지 않는다 — 왜?

`1.0 → 0.110`, `0.9 → 0.111`. **다양성 압력을 넣었는데 ILS가 올라갔다.**
오차가 아니라 **목적함수가 다르기 때문**이다.

```
MMR이 벌하는 것   :  max_{s∈S} sim(d, s)     ← 최댓값
ILS가 재는 것     :  mean_{i<j} sim(i, j)    ← 평균
```

MMR은 "가장 닮은 한 장"만 밀어낸다. 쌍둥이 한 장을 걷어내고 대신
**모두와 어중간하게 닮은** 사진이 들어오면, 최댓값은 내려가도 평균은 오를 수 있다.

**MMR로 ILS를 최적화하고 있다고 착각하면 안 된다.** 상관은 있지만 같은 것이 아니다.
[D]의 실측 분포에서는 이 어긋남이 훨씬 커진다.

### 그래서 λ_mmr을 얼마로 정할 것인가 — 지금은 정하지 않는다

이 표만 보면 0.3이 최고다(만족도 0.990, ILS 0.084). 그런데 **그렇게 결론 내면 안 된다.**

1. **만족도의 정의가 우리 가정이다.** `z(취향) + 0.5·z(사진학)`(step3 §0).
   이 가중치를 바꾸면 최적 λ_mmr이 움직인다.
2. **③의 이유로 다양성 쪽이 과대평가되고 있을 수 있다.** 만족도가 중복을 안 벌하니,
   중복을 없애서 얻는 이득만 계산되고 잃는 것은 안 잡힌다.
3. **합성 데이터다.** 실제 갤러리의 연사 비율·클러스터 크기가 다르면 표가 바뀐다.

문헌의 권장 대역도 넓다(대략 0.3~0.9). **λ_mmr은 실제 갤러리 결과를 사람 눈으로 보고
정할 값이다.** 오프라인 숫자 하나로 못 박지 않는다 — 이런 종류의 파라미터가 있다는 것을
아는 것이 이 실험의 소득이다.

## 4. [실험 C] 커버리지 — MMR이 못 하는 것

### MMR로는 왜 안 되나

MMR은 **벡터상 멀기만 하면 통과시킨다.** "서약 컷이 한 장도 없다"는 상황을
막지 못한다 — 서약 컷이 없어도 나머지가 서로 안 닮았으면 MMR은 만족한다.

**장면 커버리지는 "무엇이 없으면 안 되는가"의 문제**이고, 이건 유사도로 표현되지 않는다.
그래서 설계안은 **장면 축마다 최소 장수를 먼저 배분**하고 남는 자리를 점수로 채운다.

### 배분 결과

```
scene       갤러리   쿼터   상위N   커버리지
prep         107     3      1        3
entrance      64     2      2        2
vow           70     2      1        2
ring          16     1      0        1     ← 상위N에서 0장
kiss          28     2      1        2
family        78     2      0        2     ← 상위N에서 0장
group         63     2      3        2
bouquet       35     2      3        2
walk          53     2      1        2
snap         271     6     11        6     ← 상위N에서 과대표집
detail       175     4      6        4
unknown       40     2      1        2
```

**상위 N장에서 `ring`과 `family`가 0장이다.** 그리고 `snap`이 11장으로 3분의 1을 먹는다.
갤러리에 `family` 사진이 78장이나 있는데 추천 30장에 한 장도 없는 것이다.

> **"그게 하필 서약이면 고객은 항의한다."**
> 이건 점수가 낮아서가 아니라 **점수 상위권에 다른 장면이 몰려 있어서** 생긴 일이다.
> 점수를 아무리 잘 만들어도 안 고쳐진다 — 그래서 하드 제약이다.

### 쿼터 계산 (`coverage_quota`)

```python
quota = {s: min_per_scene for s in present}       # ① 존재하는 장면마다 최소 1장
remaining = k - min_per_scene * len(present)      # ② 남은 자리를
share = counts / counts.sum() * remaining         # ③ 갤러리 분포에 비례 배분
# ④ 반올림 잔여분은 소수부가 큰 장면부터
```

두 단계인 것이 요점이다. **최소 보장(①)** 과 **비례 배분(③)** 은 서로 다른 요구다.
①이 "빠진 장면이 없게", ③이 "실제 촬영 비중을 반영하게".

`ring`은 갤러리에 16장(1.6%)뿐이라 비례로는 0.4장이지만, ①이 **1장을 보장**한다.
반대로 `snap`은 271장(27%)이라 6장을 받는다.

```python
def _dedup_by_cluster(g, cand, score, used):
    """같은 근접 중복 클러스터에서는 점수 최고 1장만 후보로 남긴다."""
```

MMR의 부드러운 벌점과 달리 이건 **딱 자르는 규칙**이다. 연사 쌍둥이는
"조금 덜 뽑는" 게 아니라 **아예 1장만** 쓴다. 실행 결과의 `클러스터 중복 0장`이 그 효과다.

> 왜 MMR에 맡기지 않고 별도 규칙을 두나: λ_mmr을 아무리 낮춰도 **보장이 아니다.**
> 점수 차가 크면 쌍둥이 2장이 들어올 수 있다. "절대 안 됨"은 하드 규칙으로 써야 한다.
> λ 상한(step3)·하드 필터링 금지와 같은 사고방식 — **소프트 장치와 하드 장치를 구분한다.**

## 5. [실험 D] 08-25 실측 분포에서 다시 돌리면 — 커버리지가 무력해진다

지금까지의 숫자는 `scene_profile="balanced"`(설계 문서를 쓸 때 가정한 완만한 분포)다.
2026-08-25 VLM 실측은 다른 그림을 보여 줬다(`spike-report.md` 발견 3).

```bash
SCENE_PROFILE=measured ../../.venv/bin/python step4_mmr.py
```

```
[A]  점수 상위 N장            만족도 +1.791 · ILS 0.186 · 장면 6종 · 클러스터 중복 1장
     MMR (λ_mmr=0.9)         만족도 +1.791 · ILS 0.186 · 장면 6종 · 클러스터 중복 1장
     MMR (λ_mmr=0.7)         만족도 +1.766 · ILS 0.199 · 장면 6종 · 클러스터 중복 0장
     커버리지 + 클러스터 + MMR  만족도 +1.734 · ILS 0.131 · 장면 7종 · 클러스터 중복 0장

[C]  scene     갤러리   쿼터   상위N   커버리지
     prep        68      3      2        3
     kiss        28      2      3        2
     bouquet     11      1      2        1
     walk       119      4      2        4
     snap       676     16     20       16      ← 쿼터의 53%
     detail      31      2      0        2
     unknown     67      2      1        2
```

### 발견 1 — MMR이 거의 아무 일도 안 한다

`1.791 → 1.791`. λ_mmr을 0.9로, 0.8로 낮춰도 **숫자가 한 자리도 안 움직인다.**
장면 종류도 6종에서 그대로다. balanced에서 `0.799 → 0.937`로 올랐던 그 효과가 사라졌다.

이유는 §0의 구조에 있다. MMR의 이득은 **"쌍둥이를 걷어내면 다른 좋은 클러스터가 들어온다"**
에서 나온다. 그런데 갤러리의 68%가 한 장면이면 **밀려난 자리에 들어오는 것도 비슷한 스냅**이다.
바꿔 봐야 얻는 게 없다.

### 발견 2 — ILS가 오히려 올라간다 (0.186 → 0.199)

§3에서 본 어긋남이 여기서 커진다. 다양성 압력을 넣었더니 **평균 유사도가 올랐다.**
동질적인 풀에서는 "가장 닮은 한 장"을 밀어낸 자리에
**모두와 어중간하게 닮은** 사진이 들어오기 때문이다.

> **`MMR을 켰으니 다양해졌다`고 말할 수 없다.** ILS를 따로 재야 안다.
> 그리고 balanced에서도 λ_mmr=0.9에서 같은 일이 작게 일어나고 있었다(0.110 → 0.111).
> 실측 분포가 그걸 확대해서 보여 준 것뿐이다.

### 발견 3 — 커버리지 쿼터가 쏠림을 **재생산한다**

이게 가장 중요하다. `coverage_quota`는 **갤러리 분포에 비례 배분**한다.

```
balanced :  snap 271/1000 = 27%  →  쿼터 6/30  = 20%    무해
measured :  snap 676/1000 = 68%  →  쿼터 16/30 = 53%    ← 추천의 절반이 한 장면
```

**커버리지를 켰는데 추천 30장 중 16장이 `snap`이다.** 커버리지의 목적이
"장면이 골고루 들어가게"였는데, 지배적 장면이 있으면 그 지배를 **정당화해서 고정**한다.

step2에서 "scene 취향은 학습 불가하니 커버리지가 맡는다"고 정리했고
step3에서 "scene conf는 항상 0"임을 확인했다. 그 공백을 메우기로 한 장치가
**실측 분포에서는 제 역할을 못 한다.**

### 그래서 설계를 고쳐야 하나 — 아직 아니다

**판단이 갈리는 지점이 하나 남아 있다.** 이 분포가

- `../dataset`의 편향인가 (본식 사진이 없는 갤러리들만 모였다), 아니면
- 웨딩 갤러리 일반의 성격인가 (원래 스냅이 대부분이다)

**50장 표본이고 예식장 사진이 한 장도 없다.** 본식 갤러리를 확보해 같은 절차로
돌려 봐야 갈린다. 그래서 스파이크 리포트도, `plan.md`도 아직 안 고쳤다.

다만 **고쳐야 할 경우의 선택지는 지금 정리해 둘 수 있다.**

| 후보 | 내용 | 대가 |
|---|---|---|
| **장면 상한(cap)** | 한 장면이 K장의 40%를 넘지 못하게 | 실제로 스냅이 대부분인 갤러리에서 부자연스러운 목록 |
| **비례 배분 완화** | `share`를 `sqrt(counts)`로 (지배 장면을 눌러 준다) | 임의성. 근거를 대기 어렵다 |
| **축 어휘 재정의** | `walk`·`prep`을 `snap`에 합치고 다른 축으로 다양성 | 축 계약 변경 → 문서·`gallery.py`·`model_version` 동시 수정 |
| **다른 축으로 커버리지** | `framing`·`subjects`·`lighting`에 커버리지를 건다 | 장면 누락 방어가 약해진다 |

마지막 것이 흥미롭다 — **커버리지를 꼭 `scene`에 걸어야 하는 건 아니다.**
`subjects`(신부/신랑/커플/가족/친구)나 `framing`은 실측 정확도가 각각 98%·92%로
`scene`(74%)보다 훨씬 믿을 만하고, 분포도 덜 치우쳐 있을 가능성이 있다.

**변형 과제**: `select_with_coverage`의 `g.scene(i)`를 `g.tags[i]["subjects"]`로 바꿔
measured 프로파일에서 돌려 보라. 장면 종류 대신 인물 구성이 골고루 들어가는가?
그게 고객이 원하는 다양성에 더 가까운가?

### 한 줄 정리

> **STEP 3까지가 "각 사진을 얼마나 좋다고 볼 것인가"였다면,
> STEP 4는 "그 점수로 어떤 30장을 만들 것인가"다.**
> 점수는 한 장의 성질이고, 중복·누락은 목록의 성질이다. 다른 단계가 필요하다.
> 그리고 [D]가 덧붙인다 — **그 단계의 효과는 갤러리 분포에 달려 있다.**

## 7. 남은 질문 → step5

STEP 4는 지표를 네 개나 썼다. 그런데 이런 질문에 아직 답을 못 한다.

```
① 만족도 0.937과 0.847의 차이는 진짜인가, 우연인가?
② 고객 한 명(#0)으로 본 결과를 몇 명까지 늘려야 주장할 수 있나?
③ λ_mmr=0.3이 0.5보다 낫다고 말하려면 표본이 얼마나 필요한가?
```

**전부 통계 문제다.** step4의 모든 표는 **고객 1명·시드 1개**로 뽑은 것이라
그대로 결론을 내면 안 된다. step5가 그 도구(신뢰구간·검정력·필요 표본 수·군집 부트스트랩)를
만들고, 로드맵 #1의 쌍 비교 실험 설계를 확정한다.

## 부록 — STEP 4 한 장 요약

| 절 | 질문 | 답 |
|---|---|---|
| 0 | 점수 상위 N장이 왜 안 되나 | 점수는 한 장의 성질, 중복·누락은 목록의 성질 |
| 0 | 왜 웨딩에서 특히 심한가 | 연사. 클러스터당 3.1장, 같은 클러스터 코사인 0.885 |
| 1 | MMR이 왜 O(K·N)인가 | 벌점이 `max`라서 새로 뽑은 것과의 유사도만 갱신하면 된다 |
| 1 | λ가 두 개인데 뭐가 다른가 | `λ_score`=prior↔pref(증거의 함수), `λ_mmr`=관련성↔다양성(고정) |
| 2 | 다양성은 정확도를 깎지 않나 | 연사 구조에서는 **반대**. 쌍둥이 2·3번은 한계 효용이 0 |
| 2 | 평균 만족도만 보면 왜 안 되나 | 30장이 전부 같은 컷이어도 평균은 높다 |
| 2 | 커버리지는 왜 만족도가 낮나 | 최소 장수를 강제로 채우느라 낮은 점수를 넣는다. 의도된 교환 |
| 3 | λ_mmr=0은 왜 붕괴하나 | 점수가 식에서 사라진다. 첫 장은 사실상 무작위 |
| 3 | ILS가 왜 단조 감소가 아닌가 | MMR은 **최댓값**을, ILS는 **평균**을 본다 |
| 3 | λ_mmr을 얼마로 하나 | **지금 안 정한다.** 실제 갤러리를 사람 눈으로 보고 정할 값 |
| 4 | MMR으로 커버리지가 안 되나 | 안 된다. "없으면 안 되는 것"은 유사도로 표현이 안 된다 |
| 4 | 쿼터는 어떻게 계산하나 | 최소 1장 보장 + 나머지를 갤러리 분포에 비례 배분 |
| 4 | 왜 클러스터 dedup을 따로 두나 | MMR은 **보장**이 아니다. "절대 안 됨"은 하드 규칙 |
| 5 | 실측 분포에서 MMR은 | 거의 작동 안 함 (1.791 → 1.791) |
| 5 | 실측 분포에서 커버리지는 | 쏠림을 **재생산**한다 (snap 쿼터 16/30 = 53%) |
| 5 | 그럼 설계를 고치나 | **아직.** 데이터셋 편향인지 갤러리 성격인지 미확정 |

**외워둘 숫자 7개**

```
0.885 / 0.383 / 0.017 = 같은 클러스터 / 같은 장면 다른 클러스터 / 무관한 두 장의 코사인
3.1장                 = 클러스터당 평균 장수 (1,000장 → 322 클러스터)
0.799 → 0.937         = 상위 N장 → MMR(0.5)의 만족도. **다양성이 이득인 경우**
−0.027                = λ_mmr=0의 만족도 붕괴
0장                   = 상위 N장에 들어간 `ring`·`family` 장수 (갤러리에는 16·78장)
16/30 (53%)           = 실측 분포에서 커버리지 쿼터가 `snap`에 준 자리
1.791 → 1.791         = 실측 분포에서 MMR을 켠 효과. 아무 일도 안 일어난다
```
