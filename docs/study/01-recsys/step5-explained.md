# STEP 5 — 62%는 우연인가: 실험 설계와 지표

`lab/step5_eval.py` 해설 · 2026-08-25

> STEP 1~4는 전부 **숫자를 만드는** 일이었다. 0.484, 1.295, 0.937 …
> 그런데 그 숫자들은 **고객 12명·시드 하나**로 뽑은 것이다. 그대로 믿어도 되나?
> STEP 5는 만든 숫자를 **판정하는** 도구다. 그리고 이 스텝의 결론은 학습으로 끝나지 않는다 —
> **로드맵 #1의 실험 설계(몇 명 × 몇 쌍)를 여기서 정한다.**
> 앞 단계 해설: `step4-explained.md`

## 0. 이 스텝만 성격이 다르다

step1~4는 "무엇을 만들 것인가"였고, step5는 **"만든 것을 어떻게 믿을 것인가"** 다.
그래서 새 알고리즘이 없다. 대신 도구가 여섯 개 나온다.

| 도구 | 답하는 질문 | 실험 |
|---|---|---|
| Wilson 신뢰구간 | 이 62%의 진짜 값은 어디쯤인가 | A |
| 이항검정 p값 | 0.5인데 운으로 이만큼 나올 확률은 | A |
| 필요 표본 수 | 이 차이를 잡으려면 몇 쌍이 필요한가 | B |
| 검정력 시뮬레이션 | 우리 파이프라인으로 실제 몇 명 × 몇 쌍인가 | C |
| 사람 단위 부트스트랩 | 같은 사람의 답은 독립이 아닌데 | D |
| leave-one-out | 12쌍뿐일 때 평가를 짜내려면 | E |

그리고 마지막 둘은 **지표 자체**에 관한 것이다 — 실사용 지표(F)와,
지표를 정하기 전에 알아야 할 것(G).

> **왜 지금인가.** step4에서 만족도 0.937과 0.847을 비교했다. 그 차이가 진짜인지
> 우연인지 **우리는 아직 말할 수 없다.** 도구가 없으면 튜닝은 자기기만이 된다.

## 1. [실험 A] 같은 62%인데 판정이 정반대다

```
표본(쌍)   맞힌 수   정확도        95% CI          p값     판정
   24        15    0.625   [0.427, 0.788]   0.1537   우연과 구분 안 됨
   50        31    0.620   [0.482, 0.741]   0.0595   우연과 구분 안 됨
  100        62    0.620   [0.522, 0.709]   0.0105   유의 (0.5 초과)
  300       186    0.620   [0.564, 0.673]   0.0000   유의
 1000       620    0.620   [0.590, 0.650]   0.0000   유의
```

**정확도는 다섯 줄 모두 0.62다.** 그런데 24쌍이면 아무 말도 못 하고 100쌍이면 말할 수 있다.

### 신뢰구간을 읽는 법

24쌍의 구간은 `[0.427, 0.788]`이다. **0.5를 포함한다** → "진짜 실력이 0.5(=동전 던지기)여도
이 정도 결과는 나올 수 있다"는 뜻이다. 100쌍에서 `[0.522, 0.709]`로 0.5가 빠지면
비로소 "우연보다 낫다"고 말할 수 있다.

> **Wilson을 쓰는 이유.** 흔히 배우는 정규근사 `p ± 1.96·√(p(1−p)/n)`은
> n이 작거나 p가 0/1에 가까우면 구간이 [0,1] 밖으로 나가거나 실제보다 좁아진다.
> 24쌍짜리 표본에서는 그 오차가 결론을 바꾼다. Wilson은 같은 계산량으로 더 정직하다.

### p값을 읽는 법 (그리고 흔한 오독)

`p = 0.1537`은 **"진짜가 0.5인데 운으로 15/24 이상 맞을 확률이 15.4%"** 다.

- ❌ "우리가 맞을 확률이 15%"
- ❌ "0.5일 확률이 15%"
- ✅ "0.5라고 가정했을 때 이런 결과가 나올 확률이 15%"

15%는 흔한 일이다. 그래서 기각하지 못한다.

### 실무 규칙

> **정확도만 쓰고 표본 수를 안 쓴 리포트는 읽을 수 없는 리포트다.**
> `홀드아웃 정확도 62% (n=24, 95% CI [0.43, 0.79], p=0.15)` — 이렇게 써야 한다.
> 멘토가 "62%면 괜찮은데요?"라고 할 때 스스로 방어할 수 있어야 한다.

## 2. [실험 B] 필요한 표본 수 — 제곱으로 커진다

```
진짜 정확도    검정력 0.8   검정력 0.9
   0.55           617         853
   0.60           153         211
   0.65            67          92
   0.70            37          50
   0.80            15          20
```

### 왜 이렇게 급격한가

```
n ≈ [ (z_α·√(p₀(1−p₀)) + z_β·√(p₁(1−p₁))) / (p₁ − p₀) ]²
                                              └────────┘
                                          이 차이가 분모, 그리고 전체가 제곱
```

**차이가 절반이 되면 표본은 4배가 필요하다.** 0.60(차이 0.10)에서 153쌍,
0.55(차이 0.05)에서 617쌍 — 정확히 4배다.

이게 무서운 이유: **우리 문제는 차이가 작을 가능성이 높다.** step2에서 봤듯
설계 규칙 쌍은 일부러 어려운 쌍이라 천장이 0.662다. 즉 잘해야 0.6~0.65 대역이고,
그 대역은 **수십~수백 쌍**을 요구한다.

### 설계안 §6이 여기서 무너진다

`plan.md` §6은 이렇게 적혀 있다.

> 12쌍 중 9쌍으로 학습 → 나머지 **3쌍**의 선택을 맞추는 비율. 팀원·지인 **5~10명**

홀드아웃이 **3 × 5~10 = 15~30쌍**이다. 위 표와 대면:

| 진짜 정확도 | 필요 | 우리가 확보하는 것 |
|---|---|---|
| 0.65 | 67쌍 | 15~30쌍 ❌ |
| 0.70 | 37쌍 | 15~30쌍 ❌ |
| 0.80 | 15쌍 | 15~30쌍 △ |

**0.70이 나와도 유의성을 만들지 못한다.** 0.80이 나와야 겨우인데, 천장이 0.662라
구조적으로 불가능하다. **이 실험 설계로는 어떤 결과가 나와도 주장할 수 없다.**

> 이건 "결과가 나쁠 것"이라는 예측이 아니다. **결과와 무관하게 결론을 못 낸다**는
> 산수다. 실험을 돌리기 **전에** 알 수 있고, 알아야 하는 종류의 문제다.

## 3. [실험 C] 그럼 몇 명 × 몇 쌍인가 — 실제로 돌려 본 검정력

표는 "진짜 정확도가 p₁이라면"의 가정이었다. 그럼 **우리의 p₁은 얼마인가?**
합성 고객에게 실제로 학습·평가를 시켜 300회 반복했다.

```
사람 수  학습쌍/인  홀드아웃/인  총 홀드아웃  평균 정확도  검정력
   8         9          3          24       0.480     0.03   ← 설계안 §6 그대로
   8        30         20         160       0.601     0.79
   8        30         50         400       0.600     0.96
  10        60         60         600       0.631     1.00
  20        30         50        1000       0.601     1.00
```

### ① 설계안대로 하면 검정력 0.03이다

첫 줄이 `plan.md` §6의 설계다. **검정력 0.03** — 진짜로 효과가 있어도
100번 중 3번만 잡아낸다. 게다가 평균 정확도가 **0.480으로 0.5 아래**다.
학습 9쌍으로는 33차원을 못 배우기 때문이다(step2에서 이미 본 것).

**학습 쌍이 부족하면 정확도 자체가 안 오르고, 홀드아웃이 부족하면 오른 정확도를 증명 못 한다.**
이 실험 설계는 두 가지를 동시에 틀렸다.

### ② 사람 수보다 사람당 쌍 수가 먼저다

```
20명 × 30학습/50홀드  →  총 1000쌍, 정확도 0.601, 검정력 1.00
10명 × 60학습/60홀드  →  총  600쌍, 정확도 0.631, 검정력 1.00
```

**절반 인원인데 정확도가 더 높다.** 학습 쌍이 30 → 60으로 늘면
개인 취향 추정이 좋아져 p₁ 자체가 올라간다(0.601 → 0.631).
사람을 늘리는 것은 총 쌍 수만 늘릴 뿐 p₁을 못 올린다.

> **실무 번역**: "10명 모으기"보다 "한 사람에게 더 오래 답하게 하기"가 싸고 효과적이다.
> 쌍당 약 8초로 잡으면 120쌍은 **15~20분**이다. 팀원에게 부탁할 만한 크기다.

### ③ 그런데 사람 수에도 하한이 있다 → [D]

이 표는 **모든 쌍을 하나의 이항으로** 세었다. 그게 맞나? 아니다.

## 4. [실험 D] 같은 사람의 쌍은 독립이 아니다

```
사람별 정확도: [0.64  0.44  0.50  0.82  0.58  0.52  0.56  0.64]
전체 평균 0.588  (8명 × 50쌍 = 400쌍)

순진한 이항 95% CI      [0.539, 0.635]   폭 0.096
사람 단위 부트스트랩 CI   [0.520, 0.667]   폭 0.147   ← 1.5배 넓다
```

### 무엇이 문제인가

400쌍을 "동전 400번"으로 세면 **모든 쌍이 독립이고 성공 확률이 같다**고 가정한 것이다.
그런데 사람별 정확도를 보라 — **0.44부터 0.82까지 흩어져 있다.**

- 취향이 뚜렷한 사람은 잘 맞는다 (0.82)
- 의견이 별로 없는 사람은 동전 던지기다 (0.44)

같은 사람의 50쌍은 그 사람의 "맞는 정도"를 공유한다. 즉 **정보량이 50쌍어치가 아니다.**
무시하면 구간이 실제보다 좁아지고 → **"유의하다"고 잘못 선언한다.**

### 사람 단위 부트스트랩

```python
boot = [per_person[rng.integers(0, n_people, n_people)].mean() for _ in range(5000)]
#                 └─ 사람을 복원추출. 쌍이 아니라 사람이 표본 단위 ─┘
blo, bhi = np.percentile(boot, [2.5, 97.5])
```

**표본 단위가 무엇인지**를 정하는 것이 전부다. 우리 실험에서 새로 데려올 수 있는 것은
사람이지 쌍이 아니다 → 사람을 재표집한다.

### 두 개의 하한이 있다

여기서 [C]와 합쳐 결론이 나온다.

| | 무엇이 정하나 | 왜 |
|---|---|---|
| **사람당 쌍 수** | 정확도 p₁ + 이항 검정력 | 학습이 부족하면 p₁이 안 오른다 |
| **사람 수** | 부트스트랩 구간의 폭 | 사람이 표본 단위. 8명은 빠듯하다 |

8명의 부트스트랩 구간 `[0.520, 0.667]`은 0.5를 **간신히** 벗어난다.
사람이 6명이었다면 넘어갔을 것이다. **둘 다 늘려야 한다** — 하나로 다른 하나를 못 산다.

## 5. [실험 E] 12쌍뿐일 때 — leave-one-out

```
9/3 분할 평균 정확도 : 0.478   (사람당 홀드아웃 3쌍)
LOO 평균 정확도      : 0.486   (사람당 12번 평가)
```

12쌍 중 1쌍을 빼고 11쌍으로 학습 → 뺀 1쌍을 예측. 이걸 12번 반복한다.
홀드아웃을 따로 떼지 않으므로 **학습 데이터를 낭비하지 않는다.**

### 무엇을 주고 무엇을 안 주나

| | LOO가 주는 것 | LOO가 **안** 주는 것 |
|---|---|---|
| 평가 횟수 | 3 → 12회 (4배) | |
| 측정 잡음 | 줄어든다 | |
| 독립 표본 | | **아니다.** 같은 12쌍을 재사용 |
| 사람 간 독립성 | | 그대로. 사람 수는 안 늘어난다 |
| 편향 | | 11쌍 학습이라 **조금 비관적** |

> **"표본이 12배로 늘었다"가 아니라 "측정 잡음이 줄었다"로 읽어야 한다.**
> LOO 12회는 독립 12표본이 아니다. p값 계산에 n=12를 그대로 넣으면 과신이 된다.

그리고 두 숫자 모두 **0.5 아래**다(0.478, 0.486). LOO로 짜내도
12쌍으로는 배울 것이 없다 — step2 결론의 재확인이다.

## 6. [실험 F] 실사용 지표 — 대리 지표만 올리지 않기

```
수락 패턴 A(상위 집중) [1,1,1,0,1,0,0,1,0,0] → nDCG@10  0.961
수락 패턴 B(하위 집중) [0,0,1,0,0,1,0,1,1,1] → nDCG@10  0.598
두 경우의 수락률은 0.50으로 같다 — 수락률은 순서를 못 본다.

수락률 0.70 · 후회율 0.29
```

### nDCG — 설득력은 순서에 있다

같은 5장을 수락했는데 nDCG가 0.961 vs 0.598이다. **상위에 몰렸는가**의 차이다.

```
DCG = Σ gain_i / log2(i+1)      ← 순위가 낮을수록 로그로 할인
nDCG = DCG / 이상적 순서의 DCG   ← 0~1로 정규화
```

우리 서비스에서 왜 중요한가: 부부는 30장을 **위에서부터** 본다. 좋은 사진이
25번째에 있으면 그 전에 지친다. CLAUDE.md의 *"설득해서 빨리 고르게 하는 기능"* 이
계량되는 자리가 nDCG다.

### 후회율 — "전체 수락" 버튼의 방패

수락률 0.70은 좋아 보인다. 그런데 담은 것의 **29%를 나중에 다시 뺐다.**

> 수락률은 **부풀리기 쉽다.** "전체 수락" 버튼 하나면 1.0이 된다.
> 그래서 반드시 후회율(`unselected_at` 비율)과 함께 본다.
> 지표가 조작 가능하면 그 지표만 좋아지는 방향으로 시스템이 굴러간다.

### 대리 지표와 진짜 지표

| | 지표 | 성격 |
|---|---|---|
| 오프라인 | 홀드아웃 쌍 정확도 | **대리 지표.** 지금 잴 수 있다 |
| 실사용 | nDCG · 수락률 · 후회율 · 라운드 수 | **진짜 지표.** 서비스가 떠야 잰다 |

쌍 정확도를 올리는 튜닝이 수락률을 올린다는 **보장은 없다.**
지금 쌍 정확도를 쓰는 것은 그것뿐이라서지, 그게 목적이라서가 아니다.

> 여기에 하나 더 — **수락률에는 노출 편향이 있다.** 우리가 추천하지 않았으면
> 부부가 아예 안 봤을 사진이다. "추천한 것 중 담은 비율"은 추천 자체가 만든 숫자다.
> 08-22에 주지표를 홀드아웃 쌍 정확도로 바꾼 이유가 이것이다.

## 7. [실험 G] 태그 오차가 실험 예산을 정한다

[B]는 "진짜 정확도가 p₁이라면"의 표였다. [C]는 우리 p₁을 쟀다.
그런데 그 p₁은 **태그가 완벽하다는 가정** 위에 있었다. step3 [E]의 실측 오차를 넣으면:

```
학습쌍/인   태그 완벽   필요 홀드아웃    실측 오차   필요 홀드아웃
   12       0.539         964        0.462    불가 (≤0.5)
   30       0.605         153        0.561         428
   60       0.646          67        0.590         189
```

### ① 학습 12쌍 + 태그 오차 = 0.462. 증명할 것이 없다

**0.5 아래다.** 표본을 아무리 늘려도 "우연보다 낫다"를 만들 수 없다.
온보딩 12쌍만으로 실험을 설계하면 안 되는 이유가 여기서 확정된다.

### ② 필요 표본이 153 → 428쌍 (2.8배)

정확도가 0.605에서 0.561로 **0.044 내려갔을 뿐인데** 필요 표본이 2.8배가 된다.
[B]에서 본 제곱 법칙이 그대로 작동한다.

> **태그 품질은 학습 문제이기 전에 실험 예산 문제다.**
> VLM 프롬프트를 고쳐 `scene`을 74% → 85%로 올리는 작업(spike-report 다음 할 일 #1)이
> **실험 참가자 인원을 줄여 준다.** 두 작업이 별개가 아니다.

### ③ 이 숫자는 하한이다

`required_pairs`는 사람 간 분산을 무시한 이항 계산이다. [D]에서 부트스트랩 구간이
이항 구간의 약 1.5배였으므로 — 분산으로는 약 2.3배 — **실제 필요량은 2배 이상**으로 잡아야 한다.

## 8. 종합 — W1–2 실험 설계 확정안

STEP 5의 산출물은 지식이 아니라 **결정**이다.

### 현행 설계안 §6 (그대로 두면 안 된다)

```
12쌍 중 9쌍 학습 → 3쌍 검증 · 5~10명   →  총 홀드아웃 15~30쌍
                                          정확도 0.480 · 검정력 0.03
```

### 실습 근거 권고안

```
사람 10명 × 120쌍 (학습 60 + 홀드아웃 60)   →  총 홀드아웃 600쌍
                                              정확도 0.631 · 검정력 1.00
1인 소요 15~20분 (쌍당 약 8초)
```

근거를 하나씩 대면:

| 결정 | 값 | 근거 |
|---|---|---|
| 사람당 **학습** 쌍 | 60 | [C] — 30쌍이면 p₁ 0.601, 60쌍이면 0.631. p₁을 올리는 유일한 손잡이 |
| 사람당 **홀드아웃** 쌍 | 60 | [G] — 태그 오차 시 필요 189쌍, ×2 안전계수 = 380. 10명이면 600 ✅ |
| **사람 수** | 10 | [D] — 8명 부트스트랩 구간이 0.5를 간신히 벗어난다. 여유가 필요 |
| 보고 형식 | 정확도 + n + Wilson CI + p값 | [A] — 표본 수 없는 정확도는 읽을 수 없다 |
| 구간 계산 | **사람 단위 부트스트랩** | [D] — 이항 구간은 1.5배 좁게 나온다 |

**주의**: 이 숫자들은 합성 데이터 기준이다. 실제 사람의 변덕(temp)과 취향 세기가
다르면 p₁이 달라진다. **파일럿 2~3명을 먼저 돌려 p₁을 재보고 규모를 조정**하는 것이
정석이다 — 그게 [B] 표를 쓰는 방식이다.

### 설계안이 정당화되는 것

| 실험 | 관찰 | 설계 결정 |
|---|---|---|
| A | 같은 62%가 n에 따라 판정이 반대 | 리포트에 **n·CI·p값 필수 기재** |
| B | 필요 표본은 차이의 **제곱**에 반비례 | §6의 3쌍 홀드아웃은 **폐기** |
| C | 설계안 그대로면 검정력 0.03 | **사람당 쌍 수를 먼저 늘린다** |
| D | 사람 단위 CI가 1.5배 넓다 | 주지표 보고는 **부트스트랩**으로 |
| E | LOO는 표본이 아니라 잡음을 줄인다 | 12쌍 실험을 LOO로 구제할 수 없다 |
| F | 수락률은 순서를 못 보고 부풀리기 쉽다 | **nDCG + 후회율 병기** |
| **G** | **태그 오차가 필요 표본을 2.8배로** | **VLM 프롬프트 개선 = 실험 예산 절감** |

### 한 줄 정리

> **STEP 1~4가 "무엇을 만들 것인가"였다면 STEP 5는 "만든 것을 믿어도 되는가"다.**
> 그리고 이 스텝의 첫 소득은 **우리 실험 설계가 어떤 결과가 나와도 결론을 못 낸다**는
> 것을 실험 전에 알아낸 것이다.

## 9. 남은 질문 → step6

step1~5는 조각이었다. 마지막 남은 질문은 이것이다.

```
① 고객의 👍/👎를 어떻게 '쌍'으로 바꿔 evidence에 넣나
② "가족 사진 더" 같은 자연어를 어떻게 축 가중치로 번역하나
③ 시뮬레이션으로 주장할 수 있는 것과 없는 것의 경계는 어디인가
```

step6이 온보딩 → 초안 → 피드백 → 재추천을 **한 바퀴** 돌린다.

## 부록 — STEP 5 한 장 요약

| 절 | 질문 | 답 |
|---|---|---|
| 1 | 62%면 좋은 건가 | **n을 봐야 안다.** 24쌍이면 아무 말도 못 한다 |
| 1 | 왜 Wilson인가 | 정규근사는 n이 작을 때 구간이 좁거나 [0,1]을 벗어난다 |
| 1 | p=0.15의 뜻은 | "진짜가 0.5일 때 이런 결과가 나올 확률"이지 "0.5일 확률"이 아니다 |
| 2 | 필요 표본은 왜 급증하나 | 차이의 **제곱**에 반비례. 차이 절반 → 표본 4배 |
| 2 | 설계안 §6은 되나 | **안 된다.** 0.70이 나와도 유의성을 못 만든다 |
| 3 | 사람과 쌍 중 뭘 늘리나 | **사람당 쌍 수 먼저.** p₁을 올리는 유일한 손잡이 |
| 3 | 설계안대로면 검정력은 | **0.03.** 정확도도 0.480으로 0.5 아래 |
| 4 | 왜 이항 CI가 좁은가 | 같은 사람의 쌍은 독립이 아니다. 사람별 0.44~0.82로 흩어짐 |
| 4 | 그럼 어떻게 재나 | **사람 단위 부트스트랩.** 표본 단위는 사람이지 쌍이 아니다 |
| 5 | LOO가 표본을 늘려 주나 | **아니다.** 측정 잡음을 줄일 뿐. 12쌍은 여전히 12쌍 |
| 6 | 수락률만 보면 왜 안 되나 | 순서를 못 보고, "전체 수락"으로 부풀릴 수 있다 |
| 6 | 왜 nDCG인가 | 설득력은 순서에 있다. 부부는 위에서부터 본다 |
| 7 | 태그 오차의 영향은 | 정확도 0.605 → 0.561, 필요 표본 153 → 428쌍 |
| 8 | 그래서 실험은 어떻게 | **10명 × 120쌍(학습 60 + 홀드 60)**, 1인 15~20분 |

**외워둘 숫자 7개**

```
0.5            = 주지표의 기준선. 판단은 "몇이냐"가 아니라 "0.5와 구분되느냐"
617 / 153 / 67 = 진짜 정확도 0.55 / 0.60 / 0.65를 잡는 데 필요한 홀드아웃 쌍
0.03           = 설계안 §6(9/3분할·5~10명)의 검정력. 사실상 0
1.5배          = 사람 단위 부트스트랩 구간 / 순진한 이항 구간
0.478 · 0.486  = 12쌍에서 9/3분할과 LOO의 정확도. 둘 다 0.5 아래
0.961 vs 0.598 = 같은 수락 5장의 nDCG. 순서만 다르다
153 → 428      = 태그 실측 오차를 넣었을 때 필요 홀드아웃 쌍 (2.8배)
```
