# 01-recsys/lab — 이론과 함께 돌려 보는 실습

읽기만 하면 남지 않는다. 이 폴더는 **설계안(`photoselect/docs/plan.md` §3-B, §6)의 수학을
합성 데이터로 처음부터 끝까지 한 번 관통시키는** 실습이다. 별도의 토이 추천 시스템이 아니라
우리 시스템의 얇은 세로 슬라이스다.

각 스텝은 `이론 → 실행 → 출력 해석 → 자가 점검 → 변형 과제` 순서다. 이론은 스크립트 맨 위
docstring에 있으니 **파일을 열어 위쪽을 먼저 읽고 실행**할 것.

## 왜 협업 필터링(CF/MF)을 먼저 배우지 않는가

| | 고전 추천 (CF/MF) | AI 셀렉터 |
|---|---|---|
| 신호 | 다수 사용자 × 다수 아이템 상호작용 행렬 | 부부 1팀의 쌍 비교 8~12개 + 별점 |
| 핵심 가정 | "나와 비슷한 사용자가 좋아한 것" | 협업 신호가 존재하지 않음 |
| 아이템 풀 | 전체 카탈로그 공유 | 갤러리마다 사진 집합이 완전히 다름 |
| 알고리즘 | 행렬 분해, ALS, item2item | pairwise 순위 학습 + prior 결합 + 재랭킹 |
| 콜드 스타트 | 예외 상황 | **모든 사용자의 기본 상태** |

우리 문제는 추천 시스템의 하위 분야 중 **선호 도출(preference elicitation) + pairwise
ranking + 다양성 재랭킹**이다. 행렬 분해는 쓸 자리가 없다. 그래서 학습도 거기서 시작하지
않는다 (근거와 제외한 자료는 `../materials.md`).

## STEP 1 — Bradley-Terry는 로지스틱 회귀다

**이론 (요약)**
`P(i ≻ j) = π_i/(π_i+π_j)` 에서 `β = log π` 로 놓으면 `σ(β_i − β_j)`. 여기에
`β_i = w·x_i` (contextual BT)를 넣으면 `σ(w·(x_i − x_j))` — **피처 차이 벡터에 대한,
절편 없는 로지스틱 회귀**다. BT loss를 따로 구현할 일이 없다.

**먼저 읽기** — TDS "Intro to Bradley-Terry" (`../materials.md` 필수 1)
**실행** — `../../.venv/bin/python step1_bt.py`

**출력에서 볼 것**
- 직접 구현한 BT MLE와 sklearn `LogisticRegression(fit_intercept=False)`의 계수 차이가 `1e-6`
  수준 — 같은 모델이라는 증거
- 홀드아웃 정확도와 **천장**(정답 w를 써도 못 넘는 값). 사람이 확률적으로 고르므로 100%는 없다
- 아이템별 BT(사진마다 파라미터 1개)는 새 사진에 값을 줄 수 없다 → 우리는 contextual만 쓴다

**자가 점검**
1. 왜 절편(intercept)을 두지 않는가?
2. 왜 `(d, 1)`만으로 학습하면 안 되고 `(−d, 0)`을 함께 넣는가?
3. `C = 1/(2·reg)`로 맞춘 이유는? (증강 때문에 각 쌍의 손실이 두 번 세어진다)

**변형 과제** — `answer_pairs`의 노이즈를 키우면(사람이 더 변덕스러우면) 천장이 어떻게 되는가?
`D`를 20으로 올리면 같은 쌍 수에서 정확도가 어떻게 변하는가?

## STEP 2 — 피처 설계: 12쌍으로 768차원은 배울 수 없다

**이론 (요약)**
p ≫ n(파라미터가 데이터보다 많음)이면 과적합한다. 대응은 ①차원 축소 ②L2 정규화 ③데이터 증가.
L2는 "w는 0 근처"라는 가우시안 사전분포이고, 이것이 λ 곡선(step3)과 같은 사상이다.
태그 원핫은 축마다 정확히 하나가 1이므로 **축 내부의 상대값만 식별된다**.

**실행** — `step2_features.py`

**출력에서 볼 것**
- 8~12쌍 구간에서는 어떤 표현도 0.5를 겨우 넘는다. 표준편차가 크다는 것이 핵심
- 쌍이 늘면 태그(33차원)가 천장에 붙고, 임베딩(768)은 끝까지 못 따라온다
- 정규화 방향이 차원 수에 따라 **반대**다
- 실험 D: `scene`은 학습 불가로 나온다 — 쌍 규칙이 같은 scene끼리만 비교하기 때문. 버그가 아니라
  논리적 귀결이고, 그래서 장면 배분은 커버리지가 맡는다

**자가 점검**
1. 온보딩 8~12쌍과 실험용 쌍 수는 왜 다른 개념인가?
2. 태그 원핫에서 `framing` 계수 4개에 전부 +1을 더하면 예측이 어떻게 바뀌는가?
3. 랜덤 쌍으로 학습한 모델이 랜덤 쌍 평가에서 점수가 높게 나오는 이유는?

## STEP 3 — λ와 conf(axis): 증거가 적으면 덜 믿는다

**이론 (요약)**
`score = (1−λ)·prior + λ·pref`, `λ(n) = λ_min + (λ_max−λ_min)·n/(n+k)`.
베이지안 사후평균 `(n/(n+k))·데이터 + (k/(n+k))·사전`과 같은 꼴이다. k는 "사전분포가
데이터 몇 개만큼의 힘을 갖는가". conf(axis)는 축별 베타-이항 사후평균으로,
증거가 없는 축은 0이 되어 점수에 기여하지 않는다.

**실행** — `step3_lambda.py`

**출력에서 볼 것**
- 증거 0~4개에서는 λ=1(취향만)이 λ=0(사진학만)보다 **나쁘다**. 잡음에 전부를 건 결과
- 어떤 고정 λ도 전 구간에서 최적이 아니다 → λ를 증거량의 함수로 두는 이유
- 실패 모드: 12쌍 + λ=1이면 framing 한 값으로 30장이 쏠리고 저품질 컷이 섞인다
- **[E] 태그가 틀릴 때** (2026-08-25 VLM 실측 오차 주입) — 쌍 규칙 오염 33%,
  12쌍 구간의 최적 λ가 0.4 → 0.2로 이동, conf에 축 신뢰도를 곱해도 이득이 없는 이유

**자가 점검**
1. λ에 상한(0.85)을 두지 않으면 무슨 일이 생기는가?
2. prior와 pref를 z-표준화하지 않고 섞으면 λ=0.5가 왜 "반반"이 아닌가?
3. λ와 conf(axis)의 역할은 어떻게 다른가? 둘 다 있으면 중복 아닌가?
4. 태그 정확도가 74%인 축과 98%인 축이 있다. λ는 어느 쪽 영향을 받는가, conf는?

**변형 과제**
1. `LAMBDA_K`를 3과 30으로 바꿔 [B] 표를 다시 보라. 어느 쪽이 각 행의 최댓값에
   더 가까운가? 이것이 곧 λ 곡선 튜닝이다.
2. [E]의 `tag_error=1.0`을 0.5(실측 오답률의 절반 = 프로덕션 FP16이 더 나을 경우)로
   낮춰 보라. 12쌍의 최적 λ는 어디로 가는가? λ 곡선의 k를 태그 품질의 함수로
   써야 한다는 뜻인가?

## STEP 4 — MMR과 커버리지

**이론 (요약)**
`argmax_{d∉S} [ λ·Sim1(d,q) − (1−λ)·max_{s∈S} Sim2(d,s) ]`. 그리디, O(K·N), 20줄.
커버리지는 별개 문제다 — MMR은 "비슷한 것 밀어내기"일 뿐 "서약 컷 0장"을 막지 못한다.

**먼저 읽기** — Elastic Search Labs MMR 글 (구현 후 원논문)
**실행** — `step4_mmr.py`

**출력에서 볼 것**
- 점수 상위 N장에 같은 연사 클러스터가 들어온다
- MMR이 만족도까지 올리는 구간이 있다 — 쌍둥이가 자리를 잡아먹으면 다른 좋은 클러스터가 통째로
  밀려나기 때문
- **평균 만족도는 중복을 벌하지 않는다.** 지표 하나로는 이 실패를 볼 수 없어 ILS·클러스터
  중복·장면 종류를 함께 본다
- 상위 N장에서 0장이 되는 장면이 생긴다
- **ILS가 단조 감소하지 않는다** — MMR은 `max`를, ILS는 `mean`을 본다. 같은 것이 아니다

**꼭 같이 돌릴 것 — 08-25 실측 장면 분포**

```bash
SCENE_PROFILE=measured ../../.venv/bin/python step4_mmr.py
```

`snap` 68%인 갤러리에서는 **MMR 효과가 사라지고(1.791 → 1.791), 커버리지 쿼터가
쏠림을 재생산한다(snap 16/30 = 53%)**. 커버리지·MMR의 가치가 갤러리 분포에 의존한다는 것을
직접 보는 것이 이 스텝의 절반이다. 해설은 `../step4-explained.md` §5.

**자가 점검**
1. MMR만 있고 커버리지가 없으면 어떤 실패가 남는가? 반대로 커버리지만 있으면?
2. λ_mmr = 0이면 왜 만족도가 무너지는가?
3. `max` 유사도를 쓰는 이유는? 평균을 쓰면 무엇이 달라지는가?
4. 커버리지를 켰는데 추천의 절반이 한 장면이다. 쿼터 계산의 어느 줄 때문인가?

**변형 과제**
1. `_dedup_by_cluster`를 끄고(`one_per_cluster=False`) 결과를 비교하라.
   클러스터 규칙과 MMR 중 어느 쪽이 중복 제거에 더 크게 기여하는가?
2. `select_with_coverage`의 `g.scene(i)`를 `g.tags[i]["subjects"]`로 바꿔

## STEP 5 — 실험 설계: 62%는 우연인가

**이론 (요약)**
기준선은 정확히 0.5. 판단은 Wilson 신뢰구간과 이항검정으로 한다. 필요 표본 수는
차이의 **제곱에 반비례**해서 커진다. 같은 사람이 답한 쌍들은 독립이 아니므로(군집 데이터)
사람 단위 부트스트랩으로 구간을 잡아야 한다.

**실행** — `step5_eval.py`

**출력에서 볼 것 — 이 실습에서 가장 중요한 표**
- 62%는 24쌍이면 아무 말도 못 하고, 100쌍이면 유의하다
- 진짜 정확도 0.60을 잡으려면 홀드아웃 **153쌍**(검정력 0.8)
- 설계안 §6의 "12쌍 중 9쌍 학습 → 3쌍 검증, 5~10명"을 그대로 시뮬레이션하면
  **검정력 0.03** — 사실상 아무것도 증명할 수 없는 설계다
- 사람 8명 × (학습 30 + 홀드아웃 50)이면 검정력 0.96
- **[G] 태그 오차를 넣으면 필요 홀드아웃이 153 → 428쌍(2.8배).** 학습 12쌍 + 태그 오차면
  정확도가 0.5 아래라 표본을 늘려도 증명할 것이 없다

**자가 점검**
1. 검정력 0.03이라는 것은 실무적으로 무슨 뜻인가?
2. 순진한 이항 CI가 사람 단위 부트스트랩 CI보다 좁게 나오는 이유는?
3. LOO로 평가 횟수를 늘리면 "표본이 늘어난" 것인가?
4. VLM 프롬프트를 고쳐 `scene` 정확도를 74% → 85%로 올리면 실험 인원이 왜 줄어드는가?

**변형 과제** — [C]의 조합을 바꿔 우리 팀이 실제로 확보 가능한 인원·시간에서 검정력 0.8을
넘는 최소 설계를 찾아라. 그것이 곧 로드맵 #1의 실행 계획이다.
해설 §8에 실습 근거 권고안(**10명 × 120쌍**)을 정리해 뒀다 — 그대로 받지 말고
자기 계산으로 검증할 것.

## STEP 6 — 세로 슬라이스 한 바퀴

**실행** — `step6_pipeline.py`

온보딩 12쌍 → 점수 → 커버리지+MMR 30장 → 수락/거부 → evidence 추가 → 자연어 피드백 번역 →
재추천. 라운드마다 evidence·λ·수락률·nDCG·ILS가 찍힌다.

**주의** — 고객이 코드다. 수락률 상승은 내가 넣은 가정의 되풀이일 뿐이다. 이 스크립트가
증명하는 것은 **배관이 이어졌다**는 사실 하나다.

**[B] 고객 20명으로 다시 — 이 실습의 결정적 대목**
[A]의 한 사람 표에서 수락률이 0.47 → 0.83으로 오른다. **믿으면 안 된다.**
20명으로 재현하면 0.627 → 0.657, 이항검정 p=0.13으로 우연과 구분되지 않는다.
그런데 **홀드아웃 쌍 정확도는 0.545 → 0.606 (17/20, p=0.0013)** 으로 유의하게 오른다 —
루프는 실제로 작동하는데 수락률이 그것을 못 보여 준다. 학습 개선(+)과

## 실제 데이터로 갈아타는 법

교체 지점은 `gallery.py` 하나다. step1~6은 그대로 돈다.

## 이 실습이 설계안에 되먹인 것

- **로드맵 #1의 실험 설계는 검정력이 부족하다.** 사람당 홀드아웃 3쌍으로는 어떤 결과가 나와도
  주장할 수 없다 — 시뮬레이션 검정력 0.03, 정확도 0.480 (step5 [B][C]).
  **권고: 10명 × 120쌍(학습 60 + 홀드아웃 60), 1인 15~20분** (step5 §8).
  태그 오차를 감안한 값이다 — 완벽 태그 가정이면 8명 × 80쌍으로도 된다 (step5 [G])
- **VLM 프롬프트 개선은 실험 예산 절감이다.** 태그 오차가 홀드아웃 정확도를
  0.605 → 0.561로 낮추고, 필요 표본을 153 → 428쌍으로 2.8배 만든다.
  `scene` 74% → 85% 작업(spike-report 다음 할 일 #1)과 실험 인원 확보가 같은 문제다 (step5 [G])
- **취향 표현은 태그 우선.** 온보딩 규모에서 DINOv2 768차원은 태그를 못 이긴다. 임베딩은
  증거가 쌓인 뒤의 미세 재정렬용으로 남긴다 (step2 [A]) — 설계안 §3-B의 β·max_sim 항 위치와 일치
- **쌍 규칙은 scene 취향을 학습할 수 없다.** 장면 배분을 커버리지가 맡는 것은 선택이 아니라
  필연이다 (step2 [D])
- **λ와 conf는 역할이 다르다.** pref를 z-표준화하면 conf의 전역 축소 효과는 사라지고 축 간
  상대 가중만 남는다 (step3 [C])
- **평균 만족도류 단일 지표는 중복 실패를 못 잡는다.** ILS·클러스터 중복·장면 종류를 함께
  리포트해야 한다 (step4 [A])
- **λ 곡선의 k는 태그 정확도가 확정되기 전에 확정할 수 없다.** 08-25 실측 오차를 주입하면
  12쌍 구간의 최적 λ가 0.4 → 0.2로 내려간다. λ = f(n)은 증거의 **양**만 보는데 증거의
  **질**도 λ를 움직인다 (step3 [E])
- **온보딩 쌍 규칙은 태그 오차만큼 샌다.** 규칙 판정을 관측 태그로 할 수밖에 없어서,
  실측 오차에서는 후보 풀의 33%가 실제로는 규칙 위반 쌍이다. scene 정확도가
  가장 낮은 축인데 하필 규칙의 첫 조건이 "같은 scene"이다 (step3 [E]①)
- **태그 신뢰도를 conf에 곱하는 것은 답이 아니다.** z-표준화가 전역 축소를 지우고,
  부정확한 축은 conf가 이미 부분적으로 흡수한다 (step3 [E]③)
- **커버리지 쿼터가 지배 장면을 재생산한다.** 비례 배분이라 `snap` 68% 갤러리에서는
  쿼터의 53%를 한 장면에 준다. 장면 상한(cap) 도입이 후보 — **본식 갤러리 확보 후 결정**
  (step4 [D]③)
- **MMR·커버리지의 가치는 갤러리 분포에 의존한다.** 완만한 분포에서는 MMR이 만족도까지
  올리지만(0.799→0.937), 실측 분포에서는 아무 일도 안 한다(1.791→1.791). 리포트에
  **장면 분포를 함께** 적어야 한다 (step4 [D]①)
- **"MMR을 켰으니 다양해졌다"고 말할 수 없다.** MMR은 최댓값 유사도를 벌하고 ILS는
  평균을 잰다. 실측 분포에서는 ILS가 오히려 올라간다 (step4 [D]②)
- **`λ = f(evidence)`의 evidence는 종류별 가중합이어야 한다.** 반응 쌍(수락×거부)은
  온보딩 쌍과 달리 "한 축만 다름·품질 근접" 조건이 없어 랜덤 쌍에 가깝다. 같은 1개로
  세면 λ 입력이 부풀려진다 (step6 §3)
- **수락률 @round를 단독 판정 근거로 쓰면 안 된다.** 학습 개선(+)과 풀 고갈(−)의 합이라
  루프가 작동해도 평평하게 나온다. **lift 또는 라운드별 홀드아웃 정확도**를 병기해야
  한다 — `plan.md` §6의 "1차→2차 상승 = 피드백 작동" 해석은 틀릴 수 있다 (step6 [B])
- **후보 집합 정의가 설계 문서에 없다.** 실습은 `score[taken] = -inf`로 이미 담은 사진을
  빼지만, `plan.md` §3-B에는 그 규칙이 명시돼 있지 않다 (step6 §1)
