## 0. 이 스크립트가 하는 일

```
[A] 사전 등록서를 쓴다        ← 데이터를 보기 전에
[B] λ 곡선의 k를 따로 확정한다  ← 실험 참가자가 아닌 데이터로
[C] 사람 10명 데이터를 수집하고 사람 단위로 검증/시험 분할
[D] 규칙을 안 지킨 리포트를 쓴다
[E] 같은 데이터로 규칙을 지킨 리포트를 쓴다
[F] "그래서 다음에 무엇을 하는가"로 끝낸다
```

**실제 사람 데이터가 들어오면 이 스크립트의 분석부에 그대로 넣으면 된다.**
그게 이 실습의 실용적 목적이다 — 코드를 미리 짜 두는 것.

## 1. [A] 사전 등록서

```
주지표            홀드아웃 쌍 예측 정확도 (사람 단위 평균)
귀무가설          정확도 = 0.50 (우연)
의미 있는 차이     +0.10 이상
표본             사람 10명 × 120쌍 (학습 60 / 홀드아웃 60)
분할             검증 6명(하이퍼파라미터 선택) / 시험 4명(주지표 보고)
구간             사람 단위 부트스트랩 95%
보조지표          축별 정확도 5개 — BH 보정 후 보고, 단독 결론 금지
λ 곡선           실험 전에 k를 별도 추정해 확정 (튜닝 대상 아님)
```

### 여덟 줄이 앞의 다섯 스텝을 전부 담고 있다

| 줄 | 어느 스텝에서 왔나 |
|---|---|
| 주지표를 **하나**로 | step5 — 여러 지표를 보면 뭔가는 유의해진다 |
| MDE +0.10 | step5 [C] — 유의성과 크기는 다른 질문 |
| 표본 10명 × 120쌍 | 01 step5 [B][C][G] — 검정력과 태그 오차 |
| 검증/시험 분할 | step4 — 승자의 저주 |
| 사람 단위 부트스트랩 | step1 [D] — 쌍 풀링 구간의 커버리지 0.85 |
| 보조지표 BH 보정 | step5 [B] |
| λ를 튜닝 대상에서 제외 | step4 [D] + step3 [D] |

### 왜 미리 쓰는가

**데이터를 본 뒤에 하는 모든 결정이 편향의 원천이다.** 지표 선택, 기준선 선택,
부분집합 선택, 이상치 제외 — 각각은 합리적으로 보이지만 사후에 하면
결과가 좋아지는 방향으로 흘러간다(step4의 연구자 자유도).

> 사전 등록서를 쓰면 **step4와 step5의 문제 절반이 사라진다.**
> 고를 것이 없으면 승자의 저주도 없고, 지표가 하나면 다중 비교도 없다.

## 2. [B] λ 곡선을 실험 전에 못 박는다

```
추정된 k = 78  →  λ(12)=0.29  λ(60)=0.48  λ(120)=0.59
```

step3 [D]의 절차(신뢰도 곡선에 `n/(n+k)` 적합)를 그대로 쓰되,
**이 실험의 참가자와 겹치지 않는 데이터로** 추정한다(스크립트에서는 다른 시드 대역).

> 실험 데이터로 k를 정하고 같은 데이터로 성능을 보고하면 step4의 그 편향이 생긴다.
> **k 추정도 '하이퍼파라미터 선택'이다.**

여기서 k=78이 나온 것은 step3의 114와 다르다 — 사람 수(30명)와 n 격자가 달라서다.
**추정치가 그만큼 흔들린다는 것 자체가 정보다.** 실제 실험에서는 k에도 구간을 붙여야 한다.

## 3. [C] 수집과 분할

```
검증 6명 [2, 3, 4, 5, 6, 7]   시험 4명 [0, 1, 8, 9]

사람    맞힘/홀드아웃    정확도    분할
0          26/60      0.433    시험
1          43/60      0.717    시험
2          37/60      0.617    검증
...
8          50/60      0.833    시험
9          38/60      0.633    시험
```

### 사람별 정확도가 0.433 ~ 0.833으로 흩어진다

01 step5 [D]에서 본 그 분산이다. 어떤 사람은 취향이 뚜렷해 잘 맞고
어떤 사람은 동전 던지기다. **이 흩어짐이 "사람이 표본 단위"의 근거 전부다.**

### 분할은 사람 단위로

쌍 단위로 가르면 같은 사람이 검증과 시험 양쪽에 들어간다(step4 [D]).
`np.random.permutation`으로 사람을 섞어 6/4로 가른다.

## 4. [D][E] 리포트 두 장 — 같은 데이터, 다른 규칙

### 나쁜 리포트

```
┌────────────────────────────────────────────────────┐
│ 홀드아웃 쌍 정확도 62% — 우연(50%)을 크게 웃돈다.
│ 축별로 보면 `lighting`가 65%로 가장 잘 학습된다.
│ λ는 만족도가 최대인 0.4가 최적이었다.
└────────────────────────────────────────────────────┘
```

**세 문장 다 사실이다.** 계산에 오류가 없다. 그런데 네 군데가 틀렸다.

| 잘못 | 어느 스텝이 잡나 |
|---|---|
| ① 사람을 쌍으로 풀링 (구간이 좁아진다) | step1 [D] — 커버리지 0.85 |
| ② 축 5개를 보고 최고를 골라 보고 | step4 + step5 |
| ③ λ를 같은 데이터에서 고르고 같은 데이터로 자랑 | step4 |
| ④ n·구간·효과 크기가 없다 | 01 step5 [A] |

> **"틀린 계산"이 아니라 "틀린 절차"다.** 그래서 검산으로는 안 잡힌다.
> 숫자를 다시 세어 봐도 62%가 맞다. 절차를 알아야 잡을 수 있다.

### 정직한 리포트

```
┌────────────────────────────────────────────────────┐
│ [주지표] 홀드아웃 쌍 예측 정확도 (시험 4명, 240쌍)
│   0.654   95% CI(사람 단위 부트스트랩) [0.504, 0.783]   p=0.0000
│   사람별: [0.433, 0.717, 0.833, 0.633]
│   사전 등록한 MDE(+0.10) 대비: +0.154 → 충족
│ [참고] 검증 6명 평균 0.606 — 하이퍼파라미터 선택에만 사용
│ [보조] 축별 정확도 (BH 보정, 단독 결론 금지)
│   scene       갈린 쌍 0개 — 판정 불가 (쌍 규칙의 구조적 결과)
│   framing     145/229 = 0.633  [0.57, 0.69]  p=0.000  유의
│   lighting    171/262 = 0.653  [0.59, 0.71]  p=0.000  유의
│   expression  32/51 = 0.627  [0.49, 0.75]  p=0.046  —
│   subjects    27/58 = 0.466  [0.34, 0.59]  p=0.744  —
│ [사전 확정] λ 곡선 k=78 — 이 실험 데이터로 고르지 않았다
│ [한계] 축별 지표는 쌍 단위로 풀링했다 — 구간이 실제보다 좁다
└────────────────────────────────────────────────────┘
```

### 무엇이 달라졌나

```
전체 풀링:  0.625  [0.586, 0.663]   폭 0.077
시험 4명:   0.654  [0.504, 0.783]   폭 0.279
```

**점추정은 비슷한데 구간이 3.6배 넓다.**

- 사람 4명만 쓰니 표본이 작고
- 사람 단위 부트스트랩이라 사람 간 분산이 반영되고
- 그 둘이 겹쳐 구간이 벌어진다

> **그게 정직해진 대가다.** 그리고 **멘토 앞에서 방어할 수 있게 되는 값**이기도 하다.
> `[0.586, 0.663]`은 방어할 수 없다 — step1 [D]가 그 구간의 커버리지를 0.85로 쟀다.
> `[0.504, 0.783]`은 넓지만 맞는 구간이다.

### 말할 수 있는 것이 줄어든다

정직한 리포트는 **주장을 덜 한다.**

- `scene`은 "판정 불가"라고 쓴다 (갈린 쌍이 0개 — 쌍 규칙의 구조적 결과, 01 step2 [D])
- 축별 결론은 "단독 결론 금지"를 달고 나간다
- 축 간 우열은 아예 안 쓴다
- 한계 절을 스스로 적는다 (축별 지표는 쌍 풀링이라 구간이 좁다)

> 마지막 항목이 특히 중요하다. **step1 [D]가 틀렸다고 판정한 방법을 여기서 쓰고 있다.**
> 사람이 적어 축별 부트스트랩이 불가능하기 때문이다. 그럴 때 하는 일은
> 숨기는 것이 아니라 **한계로 적고 결론의 강도를 낮추는 것**이다.

## 5. [F] 리포트의 마지막 줄

```
학습 정확도 0.768 · 홀드아웃 0.625 · 격차 0.143
→ **균형.** 이 표현으로 갈 만큼 갔다. 다음 이득은 태그 품질(VLM 프롬프트)에서 온다.
```

step2 [C]의 진단표를 그대로 적용한다.

| 격차 | 진단 | 다음 이슈 |
|---|---|---|
| > 0.15 | 고분산 | 쌍을 더 받는다 (사람당 쌍 증가 우선) |
| 홀드아웃 < 0.58 | 고편향 | 태그 어휘·축 구성을 재설계한다 |
| 그 외 | 균형 | 태그 품질(VLM) 또는 다른 신호로 |

> **이 한 줄이 로드맵의 다음 이슈를 정한다. 정확도 숫자 자체보다 중요하다.**
> 리포트를 읽는 사람(멘토·팀)이 알고 싶은 것은 "몇 %냐"가 아니라
> **"그래서 뭘 할 건데"** 이기 때문이다.
