# 로컬 E2E 점검 — embedder → score → categorize (2026-09-05)

작성 2026-09-05. 로컬 wes(local 프로필) + docker pg 환경에서 배치 모듈 셋이 끝까지 도는지 실제 갤러리(1번, 822장)로
확인한 기록이다. 결론: **셋 다 정상**. 단, 처음에는 embedder venv에 torch가 없어 잡이 EMBED에 멈춰 있었고, 그 원인은
wes 쪽 venv 생성 스크립트의 macOS 분기다(§3).

## 1. 점검 환경

| 항목 | 값 |
|---|---|
| wes | local 프로필, `app.analysis.local-script-dir=scripts/lambda` (Lambda 대신 `scripts/lambda/<함수>.sh`) |
| DB | docker `wes-postgres-local` (pgvector/pg16, localhost:5432, wes/wes/wes) |
| S3 | `wes-dev-photos-233927217926` (`/wes/local/app.storage.bucket`) |
| 대상 | 갤러리 1 · 사진 822장(UPLOADED, 원본 5~13 MB JPEG) · 잡 1 (FULL) |
| venv | `embedder/.venv`(Python 3.12) · `score/.venv`(score + categorize editable, torch 2.4.1) |
| 가중치 | HF 캐시에 DINOv3·CLIP-L/14, torch hub에 ARNIQA·spaq regressor 모두 있음 — 다운로드 없음 |

단계 전이는 wes `AnalysisOrchestrator`(30초 스윕)가 맡는다. EMBED는 `photo_analysis` 관측으로 열고 닫고, SCORE는 한 번 보낸 뒤
AI 쪽이 `status`를 닫을 때까지 기다린다(`lambdaReportsStage=false`, 옛 계약). score 가 끝에서 `CATEGORIZE_COMMAND`
(= `scripts/lambda/categorize.sh`)를 서브프로세스로 띄우고, categorize 가 `ai_analysis_jobs.status`를 DONE 으로 닫는다.

## 3. 발견한 문제 — embedder venv 에 torch 없음

웹 "AI 분석" 버튼으로 만든 잡 1이 11:36 부터 `EMBED/RUNNING`, `observed_progress=0` 으로 멈춰 있었다.
로그(`$TMPDIR/wes-lambda-embedder-1.log`):

```
[setup] venv 생성: .../organic-agent-ai/embedder/.venv (Python 3.12, ...)
[setup] pip install -e .../organic-agent-ai/embedder (최초 1회)
error: .../embedder does not appear to be a Python project, as neither `pyproject.toml` nor `setup.py` are present
[embedder] python -m embedder --gallery-id 1  db=wes@localhost:5432/wes bucket=wes-dev-photos-233927217926
...
  File ".../embedder/embedder/model.py", line 26, in __init__
    import torch
ModuleNotFoundError: No module named 'torch'
```

원인 두 가지, 둘 다 wes `scripts/lib/ai-venv.sh`:

1. **torch 미설치(치명)** — `requirements.txt` 에는 의도적으로 torch 가 없고(Dockerfile 이 CPU 인덱스로 따로 깐다),
   `ai-venv.sh` 는 `uname -s = Linux` 일 때만 torch·torchvision 을 깐다. 맥에서 venv 를 새로 만들면 torch 없이 끝난다.
   주석("맥은 pypi 기본 빌드가 MPS 를 잡는다")과 달리 맥 분기에서 설치 자체를 하지 않는다.
2. **`pip install -e embedder` 실패(무해)** — embedder 에는 `pyproject.toml` 이 없다(score·categorize 에는 있다).
   래퍼가 `cd embedder` 후 `python -m embedder` 를 부르므로 import 는 cwd 로 풀려 동작에는 영향이 없지만, 매 실행 로그에 오류가 남는다.

조치(이 노트북): `uv pip install --python embedder/.venv/bin/python torch torchvision` → torch 2.14.0 · torchvision 0.29.0, MPS 사용 가능.
wes 스위퍼는 EMBED 정체를 20분(`stallAfter`) 무진행으로 판정하므로 그 전에 `scripts/lambda/embedder.sh --gallery-id 1 --job-id 1`
을 직접 띄워 잡 1을 이어 갔다.

needs_review 33/55 는 야외 자연·정원 그룹에 몰려 있다 — VLM 부모와 CLIP 부모 불일치, 최근접 배정(`nearest_tau`) 규칙이
설계대로 걸린 것이지 오류가 아니다. 리뷰 규칙의 실측 근거는 `photoselect/review-v3-design.md`.

관찰 하나: embedder 가 11:47~11:50 사이 3분간 8장만 진행한 구간이 있었다. 프로세스는 S3 소켓 read 에서 대기 중이었고
(CPU 0.6%), 같은 시각 `aws s3 cp` 로 12.6 MB 원본이 11초(1.2 MiB/s) 걸렸다. 네트워크 변동이지 코드 문제가 아니다.
원본 5~13 MB 를 장당 내려받는 구조라 로컬 embedder 속도는 회선에 좌우된다(운영 Lambda 는 같은 리전 S3).
