# photoselect — AI 셀렉터 개발 계획

wes(웨딩 사진 셀렉 서비스)의 AI 사진 추천 기능. 2026-08-22, 멘토 2차 미팅(VLM 태깅·개인화·
2차 셀렉 제안)과 화이트보드 워크플로우를 반영해 **설계를 재정의**한 버전. 2026-08-19판
(4단계 퍼널)의 결정 중 유지되는 것과 바뀐 것은 §1에 명시한다.

---

## 0. 한 줄 정의

> **AI 셀렉터** — 고객(신랑신부)이 사진을 고를 때, 고객이 납득할 추천과 이유를 제시하고,
> 피드백을 받아 다시 제시한다. 정답을 맞추는 기능이 아니라 **설득해서 빨리 고르게 하는** 기능.

- **주인공은 고객.** 작가 가치는 간접적 — 고객이 빨리·만족하며 골라야 작가의 납기가 줄고
  보정·앨범 단계의 클레임이 준다. 심사·영업 스토리에서 이 연결을 반드시 명시한다.
- **정답 라벨은 없다.** 작가마다·고객마다 "좋은 사진"이 다르다. 실제 셀렉터라는 직업이
  존재하는 이유가 "고객이 고르기 어려워서"이며, 그들은 사진 지식보다 **설득**으로 일한다.
  따라서 "작가 최종 셀렉과의 일치율" 같은 정답 기반 지표는 쓰지 않는다 (§6).
- **범위: AI 사진 추천 단일 기능.** 앨범(P1)·보정 요청(P2)·사진 진단은 범위 밖.
- 마감: SW마에스트로 최종점검 1차 **2026-11-27~28** (2차 12-02).

## 2. 원칙

1. **하드 필터 금지.** 모든 점수는 순위·제안 근거. AI가 후순위로 내린 사진도 UI에서 즉시
   되살릴 수 있다. 작가가 의도한 아웃포커스·눈감김 컷 보호.
2. **최종 결정은 고객.** AI는 `ai_recommendations`에만 쓴다. `photo_selection_items`는
   고객이 수락한 것만 MANUAL로 승격되며, `photo_selections.status`는 건드리지 않는다.
3. **취향 신호는 동의 기반.** "AI 추천" 버튼 클릭 = 내 선택·별점을 추천에 쓰는 데 동의.
   UI에 고지한다. (08-19판의 `photo_ratings` 금지는 이 동의 구조로 대체 — 폐기)
4. **사진학이 먼저, 취향은 보정.** 취향 증거가 적거나 애매하면 자동으로 사진학 점수가
   우선된다 (§3-B의 λ). 작은 표본에 과적합해 "클로즈업만 100장"이 되는 것을 막는다.
5. **LLM은 표현과 번역만.** 이유 문장 생성, 자연어 피드백 → 가중치 번역. 어느 사진을
   뽑을지는 결정적 코드가 정한다. 이미지를 외부 API로 보내지 않는다 (VLM은 자체 호스팅).
6. 이미지는 embedder의 **미리보기 파생본**(`photos.preview_key`, 1024px)만 읽는다.

## 3. 워크플로우

```
[A] 업로드 직후 · GPU EC2 온디맨드 · 갤러리당 1회 · 예산 10분/1,000장
    S3 이벤트 → wes가 EC2 start → 인스턴스가 ai_analysis_jobs(PENDING) 소비
    → 경량 3종 점수 → VLM 고정 축 태그 + 캡션 → 클러스터 + 대표컷 → photo_analysis → self stop

[B] 고객이 "AI 추천" 클릭 · Lambda · 온디맨드 · 30초 내
    선택 + 별점 충분 → 선호 분포 즉시
    부족         → 온보딩 쌍 비교 8~12쌍 → 선호 분포
    → score = (1-λ)·사진학 prior + λ·취향 + 장면 커버리지 + MMR
    → ai_recommendations(round=1) + 템플릿 이유 → [C] LLM 이유 문장 1회 일괄

[피드백 · 2차 셀렉 · Lambda B · 5초 내]
    👍/👎 · 추가 별점 · 자연어("가족 사진 더") → [C] 가중치 번역(텍스트만)
    → 재계산 → ai_recommendations(round+1) + 템플릿 이유
    고객 수락 → photo_selection_items(MANUAL) 승격. "전체 수락"은 별도 기록.
```

### 3-A. 전수 분석 (A)

| # | 처리 | 모델 | 산출 (`photo_analysis`) |
|---|---|---|---|
| A-1 | 얼굴·눈·미소 | MediaPipe Face Landmarker | `face_boxes`, eyes_open, smile |
| A-2 | 기술 품질 | ARNIQA (전체 + 얼굴 크롭) | `technical_pct` (갤러리 내 백분위) |
| A-3 | 미학 | LAION Aesthetic v2 | `aesthetic_pct` |
| A-4 | **고정 축 태그** | 오픈 VLM (7~12B, §4) | `scene` 장면(입장/서약/반지/키스/가족/단체/스냅…), `framing` 구도(클로즈업/상반신/전신/풍경형), `lighting` 조명(자연광/역광/실내/플래시), `expression` 표정, `subjects` 인물 구성 |
| A-5 | **자유 캡션** | 같은 VLM, 같은 호출 | `caption` 1문장 — 자연어 검색·이유 문장 소재 |
| A-6 | 근접 중복 클러스터 | pgvector(DINOv2) union-find | `cluster_id` |
| A-7 | 클러스터 대표 | A-1·A-2 결정적 합성 | `cluster_rank`, `rank_reason_code` |

- 경량 3종의 역할은 08-19판보다 줄었다: **① 사진학 prior, ② 클러스터 대표 선정(눈감음·흔들림
  회피), ③ 온보딩 쌍의 품질 근접 조건.** 추천 점수의 주축이 아니다.
- 고정 축은 모델을 바꿔도(12B↔31B) 호환되는 **어휘 계약**이다. 축 값 목록은 `feature-design.md`.
- `model_version` 필수. 같은 갤러리 재실행은 멱등(이미 처리된 사진 건너뜀).

### 3-B. 취향과 점수 (B)

**취향 신호** (모두 `evidence`로 집계):

| 신호 | 출처 | 비고 |
|---|---|---|
| 별점 1~5 | `photo_ratings` (해금) | 가장 정보량 큼. 있으면 주 신호 |
| 수동 선택 | `photo_selection_items` MANUAL | 읽기 전용 |
| 쌍 비교 | 온보딩 (`pair_comparison_events`) | 별점·선택이 부족할 때만 (콜드스타트) |
| 👍/👎·수락/거절·후회 | `ai_recommendations` 반응 컬럼 | 2차 셀렉의 입력이자 지표 |
| 자연어 | LLM이 축 가중치 변경으로 번역 | 선택 자체는 못 바꿈 |

**취향 표현**: 축별 태그 선호 분포 (예: framing = {클로즈업 0.6, 전신 0.3, …}) + 선택·고별점
사진의 DINOv2 벡터 (태그로 구분 안 되는 미세 취향 재정렬용).

**점수**:
```
score(p) = (1-λ)·prior(p) + λ·pref(p) + coverage_bonus(p) − mmr_penalty(p)

prior(p)  = technical_pct·w_t + aesthetic_pct·w_a           # 사진학, 갤러리 내 백분위
pref(p)   = Σ_axis conf(axis)·P(tag_axis(p) | 선호분포) + β·max_sim(p, 선호벡터)
λ         = f(evidence 수)   # 0개 → ~0.2, 12쌍+별점 20개 → ~0.7, 상한 둠
conf(axis)= 그 축의 선호가 50:50에 가까우면 0 → 애매한 축은 자동으로 사진학 우선
```
- **후보 집합**: 갤러리 전체에서 **이미 담은 사진(`photo_selection_items`)과 이전 라운드에
  제시한 사진(`ai_recommendations`)을 제외**한 나머지. 담기 여부와 무관하게 한 번 보여 준
  사진은 다시 제시하지 않는다 — 2026-08-25 로컬 실측에서 "별점만 매긴 사진은 남긴다"로
  두었더니 매 라운드 27/30이 같은 사진으로 나와 "아까 본 거잖아"가 됐다.
  추천이 다루는 것은 고객이 **아직 보지 않은 대부분**이다(1,000장 갤러리에서 온보딩
  증거는 30여 개 = 3% 남짓).
- **목표 장수와 종료**: 셀렉 목표 장수는 작가가 정한다(기본 30). 라운드마다
  `min(K, 목표 − 담긴 수)`장만 제시하고, 담긴 수가 목표에 닿으면 완료. 온보딩 쌍 비교는
  **첫 라운드 한 번**(8~12쌍)이고 이후 라운드의 증거는 담기·👍/👎·별점이다.
- **장면 커버리지**: 장면 축마다 최소 장수 보장 후 나머지를 점수로. 근접 중복 클러스터당 1장.
- **MMR**: 이미 뽑힌 것과 벡터 유사도 높으면 감점 (pgvector 위 수십 줄, DPP 불필요).
- λ 곡선·w·β는 §6 홀드아웃 정확도로 튜닝. 전부 결정적(비-LLM) → 재실행 멱등.

**온보딩 쌍 생성** (별점·선택이 부족할 때): 같은 `scene`, **한 축만 다른** 두 사진(예: 둘 다
서약, 클로즈업 vs 전신), `technical_pct`·`aesthetic_pct`가 근접한 것끼리 → "둘 다 괜찮은데
어느 스타일이 좋으세요"가 되도록. 축마다 1~2쌍, 총 8~12쌍.

### 3-C. 이유 문장과 피드백 번역 (C — Bedrock, 텍스트만)

- **이유 문장**: 기본은 태그·축 조합 템플릿("서약 장면, 자연광, 선호하신 클로즈업 스타일").
  1차 초안 확정 시에만 LLM이 100장을 1회 일괄 문장화. 2차 재계산은 템플릿 즉시.
  가드레일: photo_id 불일치 → 거부, 누락 → 템플릿 폴백. LLM은 선택을 바꿀 수 없다.
- **자연어 피드백 번역**: "가족 사진 더", "너무 클로즈업이 많아요" → structured output
  `{axis, tag, delta}` 배열만 받아 선호 분포에 반영. 번역 실패 시 무시하고 👍/👎만 반영.
- 호출은 `global.anthropic.claude-haiku-4-5…` (텍스트만 → 국외 라우팅 무방).

## 4. 실행 형태

| 워크로드 | 위치 | 이유 |
|---|---|---|
| A 전수 분석 | **GPU EC2 온디맨드** (g6, L4 24GB로 시작) | VLM 자체 호스팅 — 이미지 국내 체류, 심사 어필. 기동 4~5분 + 처리 5~6분 |
| B 초안·재계산 | Lambda 1~2GB | ML 없음, pgvector 쿼리 + 결정적 조립. 2차 5초 목표 |
| C LLM | Lambda (B와 동거 가능) | Bedrock 텍스트 호출 |

- **연동**: 큐 없음, **DB가 큐**. wes가 S3 이벤트 후 `ai_analysis_jobs` PENDING 삽입 + EC2 start
  API → 인스턴스 systemd가 PENDING 잡을 순차 소비 → COMPLETED → 잡 없으면 self stop. RUNNING
  타임아웃은 재큐. 동시 갤러리 N건은 순차(10분×N) — 소마 기간 허용.
- 같은 컨테이너 이미지, entrypoint 3개(`analyze` / `draft` / `reasons`). 모델 가중치는 AMI
  또는 이미지에 번들(런타임 다운로드 금지).
- VLM 모델·GPU 등급은 스파이크 후 확정 (§7 트랙 A). 31B가 필요하면 g6e(L40S 48GB).

## 6. 평가 — 정답 없는 문제의 지표

| 지표 | 계산 | 언제 |
|---|---|---|
| **홀드아웃 쌍 예측 정확도 (주지표)** | 학습 쌍으로 취향을 배워 **학습에 쓰지 않은** 쌍의 선택을 맞추는 비율. 우연 50% 대비 | **지금** — 아래 실험 설계 참조, GPU 불필요 |
| 수락률 @round | `accepted / 제시` 라운드별. **단독 판정 금지** — 아래 주 참조 | 실사용 |
| **lift @round** | 제시한 K장의 만족 신호 − 남은 후보 풀의 평균. 풀 고갈에 영향받지 않는다 | 실사용 |
| nDCG | 상위 순위가 실제로 더 수락됐는가 — 설득력은 순서에 있음 | 실사용 |
| 후회율 | 수락 후 `unselected_at` 비율 — "전체 수락" 부풀림 방지 | 실사용 |
| 라운드 수·완료 시간 | 제출까지 피드백 횟수·분 — 작가 납기 스토리 | 실사용 |

- 기존 골든셋 `selected` 이진 라벨과 AUC/recall@K는 **폐기**. `../dataset`은 태깅·쌍 비교
  실험의 사진 소스로만 쓴다 (라벨링 불필요).
- 지표용 로그와 학습용 신호는 **같은 테이블**(`ai_recommendations` 반응 컬럼 + 쌍 비교).

**보고 형식** — 정확도만 쓴 숫자는 읽을 수 없다. 항상 **`정확도 (n=…, 95% CI […], p=…)`**
로 적고, 구간은 **사람 단위 부트스트랩**으로 잡는다. 같은 사람이 답한 쌍은 독립이 아니라
순진한 이항 구간이 약 1.5배 좁게 나온다.

**수락률 @round 해석 주의** — "1차→2차 상승 = 피드백이 작동"은 **틀릴 수 있다.**
라운드가 진행되면 두 힘이 동시에 작용한다.

```
(+) evidence가 쌓여 취향 추정이 좋아진다
(−) 좋은 사진부터 담아 가서 남은 후보 풀이 나빠진다
수락률 = 두 힘의 합  →  루프가 작동해도 평평하게 나온다
```

시뮬레이션(고객 20명, 4라운드)에서 수락률은 0.627 → 0.657로 우연과 구분되지 않았으나
(13/20, p=0.13), 같은 실행에서 **홀드아웃 쌍 정확도는 0.545 → 0.606으로 유의하게**
올랐다(17/20, p=0.001). 라운드 품질은 **풀 고갈에 영향받지 않는 지표**
(lift, 라운드별 홀드아웃)로 판정하고 수락률은 참고로만 본다.

### 6-A. W1–2 쌍 비교 실험 설계

| 항목 | 값 | 근거 |
|---|---|---|
| 사람 수 | **10명** | 8명이면 사람 단위 부트스트랩 구간이 0.5를 간신히 벗어난다 |
| 사람당 학습 쌍 | **60** | 30쌍이면 정확도 0.601, 60쌍이면 0.631. 정확도를 올리는 유일한 손잡이 |
| 사람당 홀드아웃 쌍 | **60** | 태그 오차 시 필요 189쌍 × 안전계수 2 = 380 < 600 |
| 1인 소요 | 15~20분 | 쌍당 약 8초 |
| 총 홀드아웃 | **600쌍** | 시뮬레이션 검정력 1.00 |

**폐기된 설계**: "12쌍 중 9쌍 학습 → 3쌍 검증, 5~10명"(총 홀드아웃 15~30쌍).
그대로 시뮬레이션하면 **정확도 0.480 · 검정력 0.03** — 결과와 무관하게 결론을 낼 수 없다.
필요 표본 수는 (정확도 − 0.5)의 **제곱에 반비례**해서, 진짜 정확도 0.65를 잡는 데도
67쌍이 필요하다.

**태그 정확도가 실험 규모를 정한다.** 2026-08-25 VLM 실측 오차(scene 74% 등)를 넣으면
홀드아웃 정확도가 0.605 → 0.561로 내려가고 필요 표본이 153 → 428쌍으로 **2.8배**가 된다.
VLM 프롬프트 개선(`spike-report.md`)은 품질 작업이자 **실험 예산 절감 작업**이다.

> 위 수치는 합성 데이터(`study/01-recsys/lab/step5_eval.py`) 기준이다.
> **파일럿 2~3명으로 실제 정확도를 먼저 재고 규모를 조정한다.**

## 7. 스파이크 — 병렬 2트랙

**트랙 A (GPU)**: ① 7~12B VLM(gemma 12B / Qwen-VL 7B급) + vLLM 배치로 1,000장 처리량 실측
(목표 ≤6분) → ② 같은 100장을 31B로 태깅해 고정 축 정확도·캡션 품질 비교 → GPU 등급 확정
→ ③ EC2 온디맨드 기동·self stop·DB 큐 파이프라인. 예상 2~3주.

**트랙 B (개인화, GPU 불필요)**: ① 100장을 로컬(Mac) 소형 VLM 또는 수작업으로 고정 축 태깅
→ ② 쌍 생성 규칙 구현 → ③ **사람 10명 × 120쌍**(§6-A) → 홀드아웃 정확도 첫 숫자. **2주 내.**
파일럿 2~3명을 먼저 돌려 정확도를 재고 규모를 확정한다. 이 숫자가 50%와 구분되지 않으면
취향 표현(태그 분포)을 재검토한다 — 단, **표본이 부족해서 구분 못 한 것과 구별할 것**(§6-A).

**그 뒤**: 실제 갤러리로 커버리지+MMR 조립 테스트 (사람 눈 검수), λ 곡선 튜닝.

## 8. 리스크

- **개인화가 안 될 위험** — 쌍 12개로 취향이 안 잡히면 설계의 심장이 빈다. 트랙 B를 가장
  먼저 돌리는 이유. 폴백: 별점·선택이 충분한 고객에게만 개인화, 나머지는 사진학 + 커버리지.
- **10분 예산** — 기동 4~5분을 빼면 처리 5~6분. 12B로 안 되면 7B, 그래도 안 되면 상시 가동
  (소마 AWS 지원은 최종점검까지) 또는 AMI 가중치 굽기로 기동 단축.
- **14주 일정** — GPU 인프라·취향 학습·2차 피드백·지표 네 덩어리. P1/P2 제외로 확보.
- **취향 신호의 동의** — 별점 해금은 "AI 추천 클릭 = 동의" 고지가 전제. wes/프론트 협의.
- **VLM 태그 일관성** — 고정 축이라도 모델이 흔들리면 분포가 희석. 축 값을 enum으로 강제
  (structured output 또는 후처리 매핑).
- **논문 가능성** — "정답 없는 셀렉 + 설득 + 쌍 비교 개인화"는 기존 PIAA와 다른 축.
  쌍 비교 로그 스키마를 재사용 가능하게만 설계해 둔다.
