# photoselect — AI 1차 셀렉 개발 계획

wes(웨딩 사진 셀렉 서비스)의 AI 셀렉 기능. 루트 `docs/plan.md`의 P3(§5)를 구체화·대체하는
상세 설계다. 2026-08-19, 멘토 제안(4단계 셀렉 퍼널 + 오픈소스 연구 모델 채택)을 반영.

---

## 1. 배경 — 멘토 제안이 바꾼 것

기존 P3 설계의 열린 문제는 **"어떤 기준으로 사진을 고르는가"** 였다. 기존 Stage A는 vision
LLM에게 품질 평가를 통째로 맡겼는데, 이는 기준이 불투명하고 갤러리 전수 처리 시 원가가 크다.

멘토 제안: 셀렉을 **4개의 확립된 연구 영역으로 분해**하고, 각 영역의 오픈소스 공개 모델을
채택한다. 공개 벤치마크에서 검증된 모델 점수가 곧 **객관적 1차 기준**이 된다.

| 단계 | 연구 영역 | 답하는 질문 | 축소 예시* |
|---|---|---|---|
| ① | Portrait Image Quality Assessment | 기술적으로 정상인가? (초점·흔들림·노출·노이즈·얼굴 디테일) | 5,000 → 3,000 |
| ② | Image/Portrait Aesthetic Assessment | 미학적으로 잘 찍혔는가? (구도·조명·색감·인물 배치·배경) | 3,000 → 1,000 |
| ③ | Fine-grained Aesthetic Assessment | 비슷한 사진 중 무엇이 더 좋은가? (표정·시선·눈감김·순간 포착) | 1,000 → 300 |
| ④ | Personalized Photo Curation | 취향·다양성·중복을 반영한 최종 Top-K는? | 300 → 50 |

\* 축소 수치는 **예시이자 정렬 강도의 비유**다. 실제 목표 장수는 갤러리·상품마다 다르고,
어떤 단계도 사진을 "제거"하지 않는다 (§2 원칙 1).

이 구조가 기존 계획과 잘 맞는 이유:

- **원가 원칙과 정합** — ①②③은 경량 오픈소스 모델로 갤러리 전수 처리 가능. LLM(Bedrock)은
  ④의 근거 생성 등 소규모 호출로 물러난다. 기존 Stage A의 "클러스터별 vision LLM 호출"보다
  갤러리당 원가가 낮아진다.
- **기존 자산 재사용** — pgvector 클러스터(중복 그룹)는 ③의 입력, 장면 태그·타임라인은 ④의
  커버리지 축, Stage B의 슬롯 채우기·가드레일은 ④의 뼈대가 된다.

## 2. 원칙 (기존 계약 계승 — 위반 금지)

1. **하드 필터 금지.** 퍼널은 "탈락"이 아니라 **정렬과 후보 축소**다. 모든 점수는 순위·제안
   근거로만 쓰고, AI가 후순위로 내린 사진도 UI에서 쉽게 되살릴 수 있어야 한다. 작가가 의도한
   아웃포커스·눈감김 컷 보호 (인터뷰 결론).
2. **`photo_ratings` 접근 금지.** 개인 취향 신호는 정책상 AI 입력에서 제외. ④의 "개인화"는
   **현재 셀렉 세션의 수동 선택**(`photo_selection_items`의 MANUAL 행, 읽기 전용)과 실시간
   상호작용 신호만 쓴다.
3. **최종 결정은 사람.** 자동 확정·제출 금지. `photo_selections.status` 불변.
4. **LLM은 소규모 호출만.** 갤러리 전수 스캔에 LLM·대형 멀티모달 모델을 쓰지 않는다.
5. 이미지는 embedder가 만든 **미리보기 파생본**(`photos.preview_key`)만 읽는다.

## 3. 단계별 설계

> 단계별 논문 출처·벤치마크 수치·라이선스 검증은 `research.md` (2026-08-19 조사). 후보
> 목록은 그 결과를 반영한 상태다 — 비상업 라이선스 모델(pyiqa 경유, PIQ23, SER-FIQ/CR-FIQA,
> Q-Align, InsightFace 모델)은 후보에서 제외했다.

### ① Portrait IQA — 기술 품질 점수 (배치, 사진당 1회)

- **범용 NR-IQA**: ARNIQA(WACV 2024, Apache-2.0, ResNet-50 + 선형 회귀 — 1순위),
  HyperIQA(CVPR 2020, MIT), LIQE(CVPR 2023, MIT), MUSIQ(ICCV 2021, Apache-2.0),
  LAR-IQA(ECCVW 2024, 모바일급 — 라이선스 확인 후). **원본 repo 직접 사용** — `pyiqa`
  라이브러리는 PolyForm NC(비상업)라 서비스 코드에 포함 불가.
- **인물 특화 IQA는 채택 보류**: PIQ23 계열은 비상업 라이선스이고, NTIRE 2024 챌린지 1위가
  SRCC 0.554에 그칠 만큼 일반화가 미해결. 대신 **범용 점수 + 얼굴 영역 신호(③의 MediaPipe
  스택)** 조합으로 간다.
- 산출: 사진당 `technical_score` + 세부(선명도·노출·노이즈·얼굴 품질) 서브 점수.

### ② Aesthetic Assessment — 미학 점수 (배치, 사진당 1회)

- 후보: LAION Aesthetic Predictor v2(CLIP ViT-L/14 + MLP, Apache-2.0 — 임베딩 재사용 시
  사실상 무료), Charm(CVPR 2025, DINOv2-small ~22M, 구도 인지, Apache-2.0),
  TANet(IJCAI 2022, Apache-2.0), VILA(CVPR 2023, Apache-2.0 — TF 스택 감수 시).
- Q-Align(ICML 2024, AVA SRCC 0.822 SOTA)은 8B LMM + 비상업 라이선스 — 전수 스캔용이 아니라
  스파이크의 **기준선(오라클)** 및 골든셋 라벨 보조로만 검토.
- **도메인 갭 주의**: AVA 등 일반 사진 커뮤니티 데이터로 학습된 모델이 웨딩 사진의 미학
  (본식 조명, 스튜디오 연출)과 상관이 있는지가 최대 검증 포인트 (§6 스파이크).
- 산출: 사진당 `aesthetic_score`.

### ③ Fine-grained — 근접 중복 클러스터 내 상대 비교 (배치, 클러스터당 1회)

연구 축: photo triage / series photo selection (예: Automatic Triage for a Photo Series,
SIGGRAPH 2016) — "거의 같은 사진 묶음에서 최고 컷 고르기"는 독립 연구 영역이다.

- 입력: 기존 pgvector union-find 클러스터 (연사·유사 컷 그룹).
- 클러스터 내부는 절대 점수(①②)로 갈리지 않으므로 — Photo Triage(SIGGRAPH 2016)가 명시
  논증, Google Top Shot이 프로덕션 검증한 구조 — **얼굴 단위 신호로 상대 순위**를 만든다:
  - 눈 뜸/감김·미소 — MediaPipe Face Landmarker blendshapes (`eyeBlink*`, `mouthSmile*`)
    또는 랜드마크 EAR. **MediaPipe 단일 스택(코드+모델 Apache-2.0)** — InsightFace 모델과
    dlib 68 랜드마크는 비상업 라이선스라 금지
  - 표정 품질(정밀 필요 시) — HSEmotion (EfficientNet-B0, Apache-2.0)
  - 시선/얼굴 방향 — 6DRepNet(MIT) / L2CS-Net(MIT)
  - 얼굴 크롭 선명도 — ①의 범용 IQA를 얼굴 크롭에 재적용
- 산출: 클러스터별 대표 컷 + 클러스터 내 순위(`cluster_rank`). 단체 사진은 "전원 눈 뜸"
  같은 다인 집계 규칙 필요.

### ④ Personalized Curation — 최종 초안 Top-K (배치 + 대화형)

기존 P3 Stage B의 계승. 두 모양으로 나눈다:

- **초안 생성 (배치, 잡당 1회)** — 목표 장수까지 슬롯 채우기:
  - 고정 입력: 부부의 수동 선택 (불가침)
  - 중복 방지: 클러스터당 대표 우선 (③ 순위)
  - 커버리지: 장면 태그(본식/야외/스튜디오, 클로즈업/전신/단체) × `taken_at` 타임라인
    구간을 고르게 — 그리디로 시작, 필요 시 DPP류 다양성 선택 검토
  - 정렬 근거: ①②③ 점수 합성 (가중치는 골든셋으로 튜닝)
  - 선택마다 한 줄 근거 — 점수 기반 템플릿 우선, LLM은 문장 다듬기 소규모 호출만
- **실시간 재추천 (대화형, 후속 단계)** — 부부가 고르는 동안 "지금까지 고른 것과 어울리는
  다음 후보" 재정렬. 수동 선택이 늘 때마다 남은 후보의 순위를 갱신 (개인화 신호 = 세션 내
  선택뿐, 콜드스타트는 ①~③ 점수로 시작). 저지연 동기 API — P2 보정 구조화와 같은 실행 모양.
  연구 축은 PIAA/PARA(개인화 미학) 계열이지만, 1차 구현은 임베딩 유사도 기반 휴리스틱으로
  충분한지 먼저 실측.

### 가드레일 (기존 계승)

무효 photo_id 거부 · 수동 선택 불가침 · 개수 결정적 보정 · 전체 < 목표면 전부 선택 +
`shortfall` 기록 · 잡 라이프사이클(PENDING→RUNNING→COMPLETED/FAILED, 단일 트랜잭션, 멱등
재실행, FAILED만 재시도) · 완료 초안 자동 재생성 금지. 상세: `.claude/rules/pipeline.md`.

## 4. 실행 모양과 파이프라인

```
embedder (기존)          : 미리보기 생성 · pgvector 임베딩 · [확장] 얼굴 박스 · 장면 태그
photoselect 배치 Lambda  : ① 기술 점수 → ② 미학 점수 → ③ 클러스터 내 순위   (갤러리당 1회, 멱등)
photoselect 초안 Lambda  : ④ 초안 생성                                      (잡당 1회)
photoselect 동기 API     : ④ 실시간 재추천                                   (후속)
```

- 배치는 embedder 패턴 그대로: `handler.py`(EVENT) / `__main__.py`(로컬 CLI) / `job.py` /
  `db.py` / `config.py`. 이벤트 `{"galleryId": N, "jobId": M}`, wes가 실행 조건 검증 후 트리거.
- 점수 적재(①②③)와 초안 생성(④)을 **분리**한다 — 점수는 갤러리 임베딩 완료 후 미리 적재해
  두고, 초안 잡은 점수를 읽어 조립만 한다. 초안 잡이 빨라지고(15분 제한 여유), 점수는 P1
  레이아웃 등 다른 기능도 재사용할 수 있다.
- 모델 추론은 CPU(Lambda) 기준 실측. 초과 시 ONNX 경량화 → 그래도 안 되면 ECS Fargate.

## 5. DB 계약 (전부 wes Flyway 소유)

루트 `docs/plan.md` §4에 더해 점수 필드를 구체화:

| 대상 | 변경 | 쓰는 단계 |
|---|---|---|
| `photo_analysis` (신규 또는 `photos` 확장) | `technical_score`, `aesthetic_score`, 서브 점수(JSON), `cluster_id`, `cluster_rank`, 모델 버전 | ①②③ |
| `ai_selection_jobs` (신규) | 잡 상태, 갤러리당 활성 1개 부분 유니크 | ④ |

모델 버전 컬럼 필수 — 모델 교체 시 재적재 대상 식별용.

## 6. 구현 순서

1. **모델 스파이크 (최우선)** — `../dataset` 골든셋으로 단계별 후보 모델 비교:
   - 선정 기준: (a) 골든셋(작가 최종 셀렉) 상관, (b) **라이선스 — 연구용 비상업 라이선스
     배제, 가중치 공개 여부 확인** (1차 스크리닝은 `research.md` §⑦ 매트릭스 완료),
     (c) CPU 추론 속도·모델 크기(Lambda 탑재), (d) 유지보수성, (e) 특허 저촉 여부
     (버스트 셀렉 관련 US 10,671,895 등)
   - 산출: 단계별 채택 모델 확정 + 사진당 처리 시간·원가 실측 → 이 문서 갱신
2. **스캐폴드** — embedder 패턴 복제 (`photoselect/` 하위), 로컬 CLI로 골든셋 end-to-end
3. **점수 파이프라인 (①②③)** — wes 마이그레이션 협의 → 배치 Lambda → 골든셋 상관 리포트
4. **초안 생성 (④ 배치)** — Stage B 로직 + 가드레일 + 근거 생성, wes 트리거 연동
5. **평가** — 골든셋 기준 recall@K (AI 초안 Top-K ∩ 작가 최종 셀렉), 클러스터 대표 일치율,
   장면 커버리지. 목표 수치는 스파이크 후 설정
6. **실시간 재추천 (④ 대화형)** — 초안 기능이 검증된 뒤 착수
7. **배포** — Terraform (`../organic-agent-infra`), ECR 이미지, IAM

## 7. 리스크 & 열린 질문

- **도메인 갭 (최대 리스크)** — 공개 모델은 일반 사진으로 학습됐다. 웨딩 골든셋과 상관이
  낮으면 얼굴 신호(③) 중심으로 축을 옮기고, ②는 가중치를 낮춘다. 스파이크에서 판가름
- **모델 라이선스** — 연구 공개 모델 중 비상업 라이선스가 흔하다. 1차 스크리닝 결과는
  `research.md` §⑦ 매트릭스 — 채택 직전 원문 재확인 필수
- **공개 데이터셋 호스팅 유실** — Princeton Photo Triage·CUFED 배포 페이지가 이미 죽어
  있다(2026-08 확인). 외부 데이터셋 의존을 낮추고 `../dataset` 골든셋 자체 구축의 비중을
  높인다
- **CPU 추론 시간** — 수천 장 × 3~4개 모델. 미리보기 해상도 + 병렬화로 대응, 실측 초과 시
  Fargate
- **점수 합성 가중치** — ①②③을 하나의 순위로 합치는 규칙은 자의적일 수 있다. 골든셋 튜닝
  + 작가별 조정 가능성을 열어둔다
- **개인화 콜드스타트** — 세션 초반에는 개인화 신호가 없다. ①~③ 점수 순 정렬로 시작하는
  것이 기본값
- **논문 가능성 (K-Wedding Photo Curation)** — 서비스에 쌓이는 "작가 최종 셀렉"은 자연
  라벨이라 웨딩 도메인 큐레이션 벤치마크로서 가치가 있다. 단, 고객 동의·비식별화(얼굴)가
  선결 과제. 당장은 골든셋 구축 시 데이터 스키마를 재사용 가능하게 설계하는 수준으로만 대비
